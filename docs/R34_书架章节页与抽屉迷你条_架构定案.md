# R34 · 架构定案：抽屉 / 章节页 / 迷你播放条

> 用户描述（2026-11-04）：「书点进去是拆分好的章节，章名右边已合成有绿勾、有播放按钮；播放像音乐播放器，在选项卡上面有一条，显示书名/第几章/播放暂停/下一章。左上角三条杠点开是单独一页，向左滑也能打开；底部三个选项卡要收敛到左侧那一列；调音台也单独一个选项。」
>
> **本轮纯定案：实查代码 + 扒现成件 + 列联动 + 分轮。不改代码、不发包。**
> 理由：用户已多次强调「改一处后面连带着一堆东西」「不要给我软件改坏掉」。这五个改动同时落地必然翻车，按规矩先协调再动手。

---

## 0. 我理解的架构（先对齐，避免做错方向）

```
┌ ModalNavigationDrawer（☰ 点开 / 从左边缘右滑开，左滑或返回键关）────────┐
│ 抽屉（一列）                                                              │
│   书架 · 任务 · 我的音频        ← 原底栏 3 Tab 收进来                      │
│   ─────────                                                               │
│   设置 · 调音台 · 模型 · 角色音色  ← 调音台是独立一项                      │
│                                                                          │
│  内容区                                                                   │
│   顶栏：☰（开抽屉） | 当前页名 | ＋（仅书架）                              │
│   点书 → 章节页：章名 + 右侧「已合成 ✓」+ ▶ 播放                           │
│   底部常驻：任务条（上扒展开/下扒收起）                                   │
│   最底：迷你播放条（书名 / 第几章 / ⏯ / 上一章·下一章）← 原 Tab 栏位置    │
└──────────────────────────────────────────────────────────────────────────┘
```

**两处我按默认处理、不单独问**（不对再说）：
- 「向左滑打开」：官方 `ModalNavigationDrawer` 的手势是**从左边缘向右滑打开、向左滑关闭**。按官方来，不自己写 `detectHorizontalDragGestures` —— 自写手势会和 `DrawerState` 抢事件，正是「手搓出 bug」的典型。
- 「通过这三个点折叠」「三个选项卡收敛到左侧」：理解为**底栏移除、3 个目的地进抽屉一列**，抽屉由 ☰ 开合；不再额外造一个折叠组件。

## 3. 联动表（这是这轮不敢一把梭的原因）

| # | 改动 | 牵动 | 风险 |
|---|---|---|---|
| 1 | 根 `Column` 包进 `ModalNavigationDrawer` | `MainActivity.kt:289` 的 `statusBarsPadding()`、`AppBottomBar` 的 `navigationBarsPadding()`、任务条、迷你条全部变成 drawer content | edge-to-edge 安全区错位 → R33 刚修的重叠会复发 |
| 2 | ☰ 从 `DropdownMenu` 改开抽屉 | `AppTopBar.onMenu: (Int)->Unit` → `() -> Unit`；`MENU_ITEMS` 从 `AppChrome.kt` 挪进抽屉；`onMenu` 里 `modelsFrom = SETTINGS` / `refresh++` 的副作用要挪到抽屉项点击里 | 模型页返回路径、设置页刷新失效 |
| 3 | 底栏 3 Tab 删除 | `chromeOf()` 的 `activeTab` 语义变成「抽屉选中项」；`onTab` 里 `if (idx==TAB_AUDIO) refresh++` 要迁走 | 音频页列表不刷新 |
| 4 | **返回键优先级** | 现有 `BackHandler(enabled = screen != LIBRARY)`（`:135`）会抢在抽屉前面 → 抽屉开着按返回，直接回书架而不是关抽屉 | 必须新增 `BackHandler(drawerState.isOpen)` 且放在前面 |
| 5 | 点书 → 新 `Screen.CHAPTERS` | `Screen` 枚举 9→10、`when(screen)` 9→10 分支、`chromeOf` 加映射、`BackHandler` 基准、`modelsFrom`、外部「打开方式/分享」落地（`:234/240/275`）、通知 PendingIntent 回跳 | 外部导入或通知点开落错页 |
| 6 | **「已合成 ✓」按章状态** | `AudioLibrary.AudioItem` 加 `chapters: Set<Int>` → `index.json` 读写、`register()` 签名传入 `onlyChapters`、**兼容旧记录**（旧条目只有 scope 文字，得解析或标「整本」全章） | 唯一动数据 schema 的点；写错会让历史成品全不显示绿勾 |
| 7 | 迷你条「下一章」 | 现在 `PlayQueue.setTracks()` 的 tracks 是**成品列表**（一个 WAV = 一条），不是章列表；一个成品可能含多章。要做「上一章/下一章」必须定义 tracks 按什么组织 | 最容易「手搓出第二套播放器」的地方；必须复用 PlayQueue，不新开 MediaPlayer |
| 8 | 两条常驻条叠放 | 现在顺序：内容 → 任务条 → 底栏。改成 内容 → 任务条 → 迷你条；两条同时出现时谁在上、高度、点击区互斥 | 抢手势（任务条已有 `detectVerticalDragGestures`） |
| 9 | 调音台独立项 | `chromeOf(MIXER)` 保留；抽屉项 `selected` 高亮；`MixerScreen(onBack)` 现在写死回 SETTINGS | 从抽屉进调音台，返回该回哪 |

**一行都不能碰**：native / prompt v2 / `Prefs` / `Producer.start` 签名 / `bucket()` / 缓存分桶 / 任务书签 / `ProduceService` / 4B 设置 / Manifest 权限 / Gradle 依赖。

## 4. 分轮（各自独立发版，不合并）

**V1 · 抽屉壳（下一轮第一件）**
`ModalNavigationDrawer` + ☰ 开抽屉 + 左滑手势 + 返回键先关抽屉 + 底栏 3 Tab 收进抽屉一列 + 调音台独立项 + 顶栏/安全区回归验证。
**不做**章节页、不做绿勾、不做迷你条、不动 `AudioLibrary`。守恒清单：Screen 9 值、when 9 分支、refresh、外部 intent、通知回跳、`chromeOf` 映射关系。

**V2 · 点书进章节页 + 按章绿勾**
新 `Screen.CHAPTERS`（复用 `ChapterSplitter.split()` 的 `Chapter(index,title,start,end)`）；`AudioLibrary` 加 `chapters` 字段 + 旧数据兼容；章节行右侧 ✓ + ▶；▶ 走既有 `PlayQueue.setTracks/playFrom`。
先写 `index.json` 往返对拍（新记录 / 旧记录 / 整本 / 选章 / 重复产出）再动 UI。

**V3 · 全局迷你播放条**
订阅 `PlayQueue.state`，显示书名 / 当前章 / ⏯ / 上一章·下一章 / 进度；定义 tracks 语义与「下一章」边界；处理与任务条的叠放和手势互斥；点条展开全屏播放页（复用 `AudioScreen` 控件，不重写）。

**顺延**（原队列不取消，插在 V3 之后）：U2 其余 3 页下拉刷新 + 通知渠道描述清理 → 设置页「① 语言模型」沉页尾 → 沙盒标注 JSON 导入通道。

## 5. 明确不做

- 自己写横向手势开抽屉（用官方 `gesturesEnabled`）
- 第二套 MediaPlayer / 第二份播放状态（只订阅 `PlayQueue.state`）
- 新增 Gradle 依赖、`material-icons-extended`、导航库
- 为绿勾改动 `Producer.start` 签名或缓存分桶
- 无障碍 / 浮窗 / 模拟点击保活、改编剧本第三档、性能监控页（R19/R29 已钉）
