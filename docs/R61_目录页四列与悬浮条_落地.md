## 一、为什么先动数据层

v9 ⑧ 写过的硬前提不是危言耸听：`AudioItem` 只有 `bookId + scope` 文字，
`register()` 收到 `only: Set<Int>?` 后只转成「第 3 章」这句人话，索引当场丢掉；
`.chapters.json` 侧车文件写的是**全书章名**，不是这一份成品覆盖的章。
四列的「已标注 / 已合成 / 可整本顺序播」没有真值来源，画出来就是假状态。

所以本轮按**阶段 A（数据层）→ B（界面层）→ C（发布验证）**串行，A 的往返对拍不过不进 B。

## 二、阶段 A · `index.json` 加章节索引（唯一动数据结构处）

- `AudioItem` 末尾带默认值加 `chapters: Set<Int>` / `chaptersKnown: Boolean`，既有构造点零改动
- `register()` 加可选 `allChapterCount`：`only` 精确写入；整本展开 `0..n-1`，否则第四列永远不亮
- 旧数据兼容：`scope` 反推「第 3 章」「第 2–5 章」；**「整本」「选中 N 章」「整本（旧版）」一律 `known=false`**，界面显示灰，不冒充某一章已完成
- 新增四个查询入口：`latestByChapter` / `playableChapters` / `playableItems` / `audioFor`，四列与悬浮条共用同一份顺序
- `.part` 原子落盘、旧版 `audio/<bookId>.wav` 兼容分支、侧车 `.chapters.json` 全部原样保留

**6 组往返对拍 + 4 组边界**：新单章 / 新范围 / 整本展开 / 旧「第 3 章」反推 / 旧「整本」不点亮 / 旧「选中」与旧版不点亮；直接朗读成品第三列亮第四列灰、同名章取 `createdAt` 最新、越界范围与损坏数组安全降级。全过。

**三态真值来源**：已完成 = 磁盘成品；进行中 = `Producer.state` 的 `done/total`（界面明写「整本进度」，不做逐章假拆分）；未知 = 旧缓存无 `segmap` / 未开始 → 灰 + 不响应。标注结果页只读，来自 `SegPlan.readMap` + `Chunk.chapter` 过滤，无 segmap 明写「旧缓存没有逐段记录」。

**没有伪造第三条管线**：引擎只有 DIRECT / ANNOTATE 两档，`去标注` 与 `标注并合成音频` 都落 ANNOTATE，底部小条下方一行如实写「这一档跑完会一并出音频」。真正「只标注不出声」要改 Pipeline，单列一期。
