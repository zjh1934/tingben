## 二、从代码 + 真机日志读出来的根因链

用户说：「它一顿跑了一堆，结果啥也没标注」「标注和没标注都是一样，白费那个力气」。
这不是错觉，是一条完整的机制链：

```
native 不认 JSON 闭合，模型吐完 `]` 后继续输出废话直到 maxTokens
  → 产出被预算腰斩，尾部条丢失（真机 +13 日志：outChars=1676 > limit=1274）
  → parseWithMeta 四级修复只能保住「最后一个完整对象」之前的条
  → gate 全有或全无：拼回原文 ≠ 原文 ⇒ 整块判失败
  → fallback 把 500 字整块换成全旁白「平稳叙述」
  → 音频里没有任何角色区分/情绪 ⇒ 听起来「标了跟没标一样」
  → 日志只有条数/字数/160 字截取 ⇒ 用户无法自证到底标了什么
```

**所以问题不在「模型不行」，在「全有或全无的采纳策略 + 不早停 + 日志只给摘要」三者叠加。**

## 三、本版四处改动

### C1 · native JSON 数组闭合即停（改 C++，唯一一处 native 改动）
`llmGenerate` 在本项目唯一用途就是产出标注数组。加一个轻量状态机：
`inStr`（处理 `"` 与 `\"` 转义）、`jsonDepth`（字符串外的 `[`/`]`）、`jsonStarted`。
见到第一个 `[` 后才启用；`depth` 回到 0 立刻 `break` 并写 `NATIVE_JSON_CLOSE`。
**全程没出现 `[` 时行为与旧版完全一致**（模型吐纯废话仍靠 EOG/limit 退出），不会误伤。

### C2 · 逐条采纳 + 确定性补齐（核心链路，抄 Antioch 的「部分失败用默认」）
新增 `Annotator.reconcile(parsed, original) -> Reconcile(result, kept, filled, disposition)`：

- 从 cursor=0 开始逐条校验 `original.regionMatches(cursor, a.text, 0, len)`；
  第一条不合法就停，**前面标对的条目全部保留**（speaker / instruct 真进 TTS）
- 剩余原文用 `directSegments` 确定性切短句补成旁白（来源 `FILL`）
- 三档：`FULL`（全标对）/ `PARTIAL`（前段标对，尾部补齐）/ `FALLBACK`（一条没采纳）
- **不变量：`result.joinToString(""){text} == original` 仍严格成立**（gate 保留为断言）
  → 逐字契约一个字没放宽，只是不再因为尾条丢失就整块作废
- 重试条件收紧：只有 `FALLBACK` 才重试；`PARTIAL` 直接采纳，省一次几分钟的 4B 空转

> 与 Antioch 的区别（不照抄）：它是英文剧本、允许改写对白、结构全由代码做；
> 我们是中文小说逐字保真。抄的是**「单条失败不牵连整块」这一条策略**，不是它的输出格式。

### C3 · 日志把「标注过后的内容」摊开
- `ANN_CONTENT`：每块最终采纳的**逐条内容**（`[角色] 文本 → 指令 〈模型标注/程序补齐〉`），进主日志
- `ANN_DISPOSITION`：采纳档位 + 模型采纳条数 + 补齐条数 + gate 是否逐字相等
- `TTS_INPUT`：合成前每段写**最终** `text` 摘要 + `instruct` 全文 + `speaker` + `lang` + `speakerParam=null`
  （这里看到的是含身份层/风格层的最终指令，不是 4B 原始产出）
- `BlockAudit` 新增 `disposition / kept / filled / annsJson`（逐条全文，单块 8KB 上限）
- `AuditLog.contentText()`：按块输出全文；诊断页「查看标注内容」+「复制标注全文」；
  **「复制诊断信息（摘要）」也直接带最近 3 块全文**，不用用户再点一次
- 汇总新增「模型全标对 / 部分标对+程序补齐 / 一条没采纳」三档
- 向后兼容：新增字段全部 `opt*` 带默认值，旧 `run-*.jsonl` 仍能读

### C4 · 双模型协作（依据官方原文，不换权重）
- `lang`：`"auto"` → **`"chinese"`**（官方 README 167 行）。全中文书，这是实打实的适配
- 确认 `speaker` 传 `null` 对 voice_design 正确（qwen.h 285-288），写进代码注释
- `INSTRUCT_TEMPLATE_VERSION` 3 → **4**：lang 改变会影响合成结果，借 R14 既有 `voiceStamp`
  机制作废旧分段 WAV、**标注保留复用**，不新增指纹字段
- 采样参数与 `sampling-defaults.h` 逐项核对，未改动

## 四、必须订正的两条旧结论

1. **「TTS 不能并行、上下文不是线程安全」是错的。**
   `qwen.h:133-142` 明写 `qt_synthesize itself stays blocking and thread safe`，
   `max_batch > 1` 会把并发请求合成批。以前我拿「多实例 = 多份 2GB」当全部答案，不准确。
   本轮**仍不开并行**：CPU 大核就那么多、2 路抢缓存 + 内存翻倍，夜长任务未必更快；
   但结论应改成「引擎支持，端侧收益待真机量」，不是「物理上不行」。

2. **「小模型回显平行 JSON 会循环」只是工程假设。**
   它来自 Antioch `annotator.rs:113-115` 的注释，不是第三方基准实测。R21 已订正过一次，
   本轮继续只当风险假设，不当结论引用。

## 七、真机验证清单（仍是零证据，不宣称已修好）

1. `NATIVE_JSON_CLOSE` 是否出现、`outChars` 是否明显小于 `limit`
2. `ANN_DISPOSITION` 是 `FULL` / `PARTIAL` / `FALLBACK`，`kept` 是不是 0

5. 听感上相邻两段是否终于有区别（此前全 fallback 时必然没有）
