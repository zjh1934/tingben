# R61 · 目录页四列与悬浮条 · 联动表

批准来源：v9 全 8 屏预览 + 用户「很不错，说明你是听懂了，咱这一页就这么做吧」。
本轮按「先列联动表 → 阶段 A 数据层往返对拍 → 阶段 B 界面层 → 阶段 C 发布验证」串行推进，
A 未过不进 B，不一把梭。App 基线 `1.0.0+66`。

## 一、先解决硬前提（v9 ⑧）

`AudioItem` 只有 `bookId + scope` 文字（`AudioLibrary.kt:19-28`），`register()` 收到
`only: Set<Int>?` 后只转成 `scopeLabel()` 文字，索引当场丢掉。
`.chapters.json` 侧车文件写的是**全书章名**，不是这一份成品覆盖的章。
⇒ 四列的三套状态没有真值来源，必须给 `index.json` 加 `chapterIndices` 并兼容旧数据。
这是本轮**唯一动数据结构**的地方，单独阶段 A 跑往返对拍，不与界面混做。

## 三、三态真值来源（不许画假进度）

| 状态 | 来源 | 界面 |
|---|---|---|
| 已完成 | `AudioLibrary.latestByChapter` 命中该章 | 进度 100% / 播放按钮 |
| 进行中 | `Producer.state.running && resume.bookId == 本册` → `done/total` | 半透明进度条，标「整本进度」 |
| 未知 | 旧缓存无 `segmap`、旧版 `audio/<bookId>.wav`、未开始 | 灰 + 不响应点击，不冒充 |

第二列 `annotated >= 1f` 才可点进标注结果；标注结果页只读，来源 `SegPlan.readMap` +
`Chunk.chapter` 过滤，无 segmap 明写「旧缓存没有逐段记录」。

## 四、三条底部操作 → 引擎只有两条路径（如实差额）

`Producer.start(directRead=...)` 只有两档：DIRECT（不过语言模型）/ ANNOTATE（标注后一路合成出音频）。
所以 `去标注` 与 `标注并合成音频` 都落到 ANNOTATE 档，界面下方一行小字写明
「这一档跑完会一并出音频」；`直接合成音频` 落 DIRECT 档，成品 `mode=直接朗读`，
第三列亮、带「未标注」小字，第四列仍灰 —— 对应 v9 决策①。
**没有伪造第三条管线**；真正「只标注不出声」要改 Pipeline，单列一期，不在本轮。

## 六、验收要点

1. `index.json` 新旧混读往返一致，旧「整本」不被点亮成具体章
2. 勾选 1 章 / 多选 N 章，底部三条只对选中章生效
3. 直接朗读成品在第三列亮、第四列灰；标注档成品第四列亮
4. 四列左右滑时顶部标签跟着亮；点标签跳到对应列
5. 悬浮条跨页不断播，目录抽屉只列第四列亮章
6. 375px 无横向溢出，底部不压系统手势白条
