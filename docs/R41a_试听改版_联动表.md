# R41a · 调音台「试听」改版联动表（插队轮，先协调后动代码）

> 用户原话：A/B 试听看不懂；**只要两个试听按钮**——一个用「未提交（草稿）参数」合成试听，
> 一个用「已提交 / 已生效参数」合成试听；**按钮就放在提交变更附近、同一个模块里**；
> 末尾补了「返回」。
>
> 「返回」按最合理解读执行：**把「‹ 返回」也挪进吸顶状态条那一块**，常驻不随内容滚走。
> 若指的是别的返回语义，下一轮改，不追问。
>
> 本轮是插队，不是 R39 排的 R41(P1) / R42(P2)；两者顺延、不取消。

## 1. 现状实查（`MainActivity.kt` 实读，不是猜）

| 项 | 现状 | 问题 |
|---|---|---|
| 位置 | ⑨「A/B 试听」折叠区在**页面最底部**，长滚到底才见 | 用户找不到、也不懂 A/B |
| 操作 | 改文本 → 选 B 预设 → 点「合成 A」→ 点「▶ 听 A」→ 点「合成 B」→ 点「▶ 听 B」 | 6 步、两套「合成 / 播放」分离 |
| A 侧 | `active.knobs` | 名字叫 A，人不认 |
| B 侧 | `MixerPresetStore.find(c, bPresetId)?.knobs`，即**某个预设** | 用户要的不是「预设对比」，是「草稿 vs 已生效」 |
| instruct | 两边都硬写 `Prefs.voiceDescription(c)` + 固定一句 | **身份层与草稿无关**，改了音色描述后两个按钮听起来一样，又是 A vs A |
| 日志 | `MIXER_AB` / `MIXER_AB_FAIL` | 名字是开发者黑话 |
| 返回 | 滚动内容顶部单独一行 `‹ 返回`，往下滚就看不见 | 不在提交那一块 |

**最危险的一处**：旧 A/B 的「只换采样参数、instruct 两边相同」是刻意设计，但放到「未提交 vs 已生效」上就变成骗人 —— 音色身份、朗读档位也是能改的参数，试听必须整套跟着走，否则用户改了音色却听不出差别。

## 2. 改法（一句话）

**吸顶状态条那个模块内**，两个按钮 = 「试听未提交参数」/「试听已生效参数」，
点一下**合成完自动播放**，不设第二步「听 A / 听 B」；各用**整套** `MixerDraft`
（voice + knobs + perf.styleInstruct()）经 `VoiceProfile.build()` 拼 instruct，
保证草稿与已生效真不一样。底部 ⑨ 整块删除。

## 6. 验收 6 条

1. 调音台首屏（吸顶那一块）就能看到两个试听按钮，不用滚到底、不用展开任何折叠
2. 点任一按钮 = 合成 + 自动播放一步到位，页面里不再有「合成 A / ▶ 听 A」这类两步控件
3. 改了音色身份或采样但未提交 → 两个按钮分别用 `draft` / `active`，日志 `MIXER_TRIAL` 里两套 hash / voiceChars 可对照
4. 全页无 `A/B 试听 / 合成 A / 听 A / MIXER_AB` 字面量（dex 级也验）
5. 「‹ 返回」常驻吸顶；有未提交变更时点它仍弹确认，草稿不静默丢
6. 4B 设置、prompt v2、native、分桶、续跑、前台服务与 `git HEAD` 基线逐字节一致

## 7. 已知边界（如实写，不粉饰）

- 试听是 `rememberCoroutineScope()` 起的 `Dispatchers.IO`：合成期间离开页面，协程被取消，
  **可能只写出 wav 而不自动播放**，回来再点一次即可。要改成 App 级 scope 得动生命周期，本轮不做。
- 试听 wav 写在 `filesDir`，不进 `AudioLibrary`、不改 `voiceStamp`、不触发缓存作废 —— 试听**不是**制作。
- `!dirty` 时「试听未提交参数」与「试听已生效参数」内容相同，日志里会写明「与已生效一致」，不假装有差异。
- 真机仍是零证据：本轮交付的是「看得懂、点得到、两套参数真分开」，不是声音变好。
