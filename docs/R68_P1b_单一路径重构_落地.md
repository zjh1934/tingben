## 1. 做了什么

把 `Producer.run` 里 `if (direct) / else` 两套分支收成**一条直接朗读路径**，然后物理删掉只被旧分支引用的 4 个文件。

| 项 | 改前 | 改后 |
|---|---|---|
| `Pipeline.kt` | 1381 行，两套分支 | **799 行**，−582 行 |
| 旧文件 | `Adoption.kt` / `JsonSalvage.kt` / `RawDump.kt` / `AuditLog.kt` | **4 个全删** |
| `Annotator` | 20 个方法（提示词/解析/采纳/审计/断句） | 只剩 `directWithStats` / `directSegments` |
| 诊断区 | 6 处旧读取 + 3 秒定时器 + 3 个旧折叠按钮 + 原始产出复制 | 静态快照 + 两次复制 + 清理分段音频确认弹层 |
| WAV 命名 | `if (direct) direct_… else chunk_…` | 统一 `direct_%04d.wav` |
| 结构自检 | 旧符号「必须存在」 | **50 项零残留反向断言** |

**取舍**：`gateFails` 保留为 `val gateFails = 0`（合成/合并段 6 处算式不动）。恒 0 常量会被内联，改写算式只会增加断链风险；联动表原计划替换算式，按此取舍执行并如实记。
