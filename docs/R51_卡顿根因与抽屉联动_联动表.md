# R51 · 为什么这么小的软件这么卡 + 抽屉从「覆盖」改成「联动」

> 本轮**不进 V2 队列**（目录页 / 按章绿勾 / 迷你条一行没动）。
> 用户问句：「为什么这么小的软件用起来这么卡？界面切换卡得要死」「抽屉应该是左滑展开收起、和右边工作页有联动，不是覆盖」。
> 结论先行：**不是软件小就该快，是状态读在了整棵页面树的根上、页面又全量组合、还跑着三个无条件定时器；抽屉用的是官方覆盖式组件。**

---

## 一、卡顿诊断（逐条带源码坐标，不靠直觉）

### ① 最狠的一条：为 5 个「根本没用」的参数，把高频状态挂在整棵树根上

`MainActivity.kt` 改前：

```kotlin
@Composable private fun App(...) {
    val st by Producer.state.collectAsState()          // 141
    val resumeTask by Producer.resume.collectAsState() // 142
    ...
    ModalNavigationDrawer { Column {
        when (screen) { 9 个页面 ... }                  // 363~421
    }}
}
```

`Producer.state` 在制作时每块 / 每阶段 / 每秒都会更新。**App() 读了它，重组作用域就是 App() 整棵 lambda，包含 `when(screen)` 下全部 9 个页面**。
而它之所以要读，只是为了给书架页传：

```
producing = st.running, progressText = ..., onProgress = ...,
pendingTask = resumeTask?.takeIf{...}, onTasks = ...
```

**查 `LibraryScreen`(536~645) 函数体：这 5 个参数一个都没被读取过。** 纯白挂。

> 官方 Compose 性能准则原文：「read state as low in the tree as possible so fewer composables recompose」；
> 以及「把高频状态读进 `graphicsLayer` / `derivedStateOf`，别放在组合期」[citation:6][citation:5]。

**修法**：删掉 5 个参数 + App() 两个订阅；屏幕常亮抽 `KeepScreenOn()`、任务条抽 `TaskBar()`，各自在叶子订阅；续跑回调改读 `Producer.resume.value`（回调里读 `.value` 不订阅、不触发重组）。

### ② 9 个页面全是 `Column + verticalScroll`，一次性组合全部子项

```
LibraryScreen / ProduceScreen / ProgressScreen / TaskCenterScreen /
AudioScreen / SettingsScreen / ModelScreen / CastScreen / MixerScreen
全部：Column(Modifier.fillMaxSize().verticalScroll(rememberScrollState()))
```

官方与实测：`Column + verticalScroll` 无论多少子项都一次性全部组合并测量，100 项时内存 12MB，同数据 `LazyColumn` 仅 3MB [citation:7][citation:9]。设置页 / 调音台几百个控件，切页首帧 = 全量组合 + 全量 measure。

**本轮没改**：改成 `LazyColumn` 会破坏 R50 的 `onGloballyPositioned { positionInParent().y }` 锚点联动（LazyColumn 里该坐标语义不同），9 页一起动风险过大，单列下一轮。

### ③ 三个无条件定时器，闲着也在重组整页

| 位置 | 改前 | 改后 |
|---|---|---|
| `AudioScreen:1278` | `while(true){ delay(300); PlayQueue.tick() }` 无条件 3.3 次/秒 | `LaunchedEffect(pq.isPlaying)`，仅播放时 500ms |
| `TaskCenterScreen:1145` | `delay(1000); tick.value++` + `remember(refresh, tick.value/2){TaskResume.load()}` | 合成一次 `delay(2000); loadTick++`，重组减半、磁盘读频率不变 |
| `ProgressScreen:853` | `while(true){ delay(1000); tick++ }` 无条件 | `LaunchedEffect(st.running)`，没在制作就停 |

另 `MixerScreen` 的 `snapshotFlow { scroll.value to anchors.toMap() }` 每滚动一帧复制整张锚点表 → 改成只把 `scroll.value` 放进流，表在 `collect` 里现读。

### ④ 组合期同步读磁盘

各页 `remember(refresh) { BookStore.list(c) / ModelStore.* / AudioLibrary.list(c) / VoiceCast.load(c) }` 都在 **composition 主线程**解析 JSON。切页 / `refresh++` 时同步阻塞首帧。本轮未改（要改 `produceState` + 空态，牵动 9 页），单列。

### ⑤ 装的是 debug 包，这是「软件小却卡」的放大器

`build.gradle.kts`：`assembleDebug`、`isMinifyEnabled = false`、`debugImplementation(androidx.ui.tooling)`。
官方明确「**debug builds disable Compose compiler optimizations**，Always benchmark in release mode with R8 enabled」[citation:8]。debug 包带重组追踪、无 R8、ART 以 JIT 为主、无 Baseline Profile。本轮未改产物类型（换 release 会动签名/CI/7 个 .so 闸门），单列。

**所以「这么小的软件」不成立**：APK 18MB 但 Composition 树有 9 页 / 几百控件，且每次引擎更新把整棵树重算一遍。

## 二、抽屉：覆盖 → 联动

**改前**：`ModalNavigationDrawer`。官方定义是 modal = 「显示在屏幕上其他内容的顶部」，只改 DrawerContent 的 offset，**右边工作页纹丝不动**，再盖一层全屏 scrim [citation:17][citation:18]。这正是你说的「覆盖」。

**改后**：`DismissibleNavigationDrawer`。官方定义：standard drawer「pushes the page content making space for the expanded navigation」，**抽屉展开时把右侧工作页一起推走** [citation:20][citation:21][citation:17]。不用手搓手势、不用自己算 `drawerState.offset`，组件本身就是这个语义。

守恒：☰ `drawerState.open()`、从左边缘右滑 `gesturesEnabled = true`、返回键优先收抽屉、7 个目的地、`requiredWidth(240.dp)` 收窄、底部 `navigationBarsPadding()` —— **一行未改**。
`AppDrawerSheet` 仍用 `ModalDrawerSheet`（只是带样式的容器），加 `@OptIn(ExperimentalMaterial3Api::class)` 兜住 M3 1.3 的实验性标记。

## 三、联动表（改动 → 连带 → 守恒）

| # | 改动 | 连带 | 守恒 |
|---|---|---|---|
| 1 | `ModalNavigationDrawer` → `DismissibleNavigationDrawer` | AppChrome KDoc、结构自检 R46 正向符号 | 7 目的地 / 手势 / 返回键 / 240dp / 安全区 |
| 2 | App() 删 2 个 collectAsState | 书架页 5 实参、屏幕常亮、任务条、续跑回调 | `when(screen)` 9 分发 / `chromeOf` / `refresh` |
| 3 | 新增 `KeepScreenOn()` | `FLAG_KEEP_SCREEN_ON` 语义 | 零权限 / 零 WakeLock |
| 4 | 新增 `TaskBar()` | 上扒展开 / 下扒收起 / 三个跳转 | 文案与颜色逐字不变 |
| 5 | `LibraryScreen` 签名删 5 参 | 函数体零引用（已核） | 粘贴框 / 删除确认 / 建书 |
| 6 | 三个 tick 收敛 | 心跳文案 / 磁盘读频率 | 显示内容不变 |
| 7 | 锚点流去 `toMap()` | `jumpLock` 防抖 | 滚动→chip 高亮语义 |

**零改动**：4B 设置 / prompt v2 / 两条制作路径 / 缓存分桶 / 续跑书签 / native / JNI / 前台服务 / Manifest / Gradle 依赖 / `ParamSpec` / `MixerDraft` / 调音台唯一提交出口。
