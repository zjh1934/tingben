# 标注工厂 · 输出契约 `tingben.annotation/1`

> **方向变更**：端侧 4B 标注从主路撤下。标注改在元宝沙盒里逐块做完，产出本契约的 JSON，
> 导入 App 后**直接进音频合成，不再跑语言模型**。
> 本轮**只定契约 + 给示例，不接导入管线**；下一轮第一件就是把导入通道做上去。

---

## 1. 为什么要这份契约

真机日志坐实：`ANN_BLOCK_END 块 1/2 · 0 条标注 · 耗时 643428ms`。
4B 手机上跑 10 分钟、prompt 979 token、输出预算 876 token，产出被逐字 gate 整块丢弃 →
降级直读。用户听到的「不标注也不错」其实是 **A vs A**（降级平读 vs 直接朗读）。

R30 算账的结论：**拆细不是目的，是「让 4B 逐字回显原文」这个契约的副作用**。
沙盒没有 9 秒/token 的限制、没有 4096 窗口、没有电池与杀进程问题，所以工厂侧直接换成
**骨架化标注**：

- **程序**负责切句、区间、说话人别名、逐字校验（确定性，不靠模型）
- **LLM**只填 `speaker` 和 `instruct` 两个短字段，**不回显原文**
- **App**只负责把文本喂给音频模型，身份层由调音台统一固定

三角分工对齐 Antioch `annotator.rs` 的「结构归程序、导演归 LLM」和 Alexandria 的
「声音卡片 / 逐行编辑」，不是新发明。

## 2. 文件格式

一个 UTF-8 JSON 文件，对应一本书（或一次选中章节的范围）。

```jsonc
{
  "schema": "tingben.annotation/1",       // 必填，版本不符直接拒
  "generator": "yuanbao-sandbox",          // 谁标的
  "promptVersion": "skeleton-v1",          // 工厂侧用的标注 prompt 版本
  "bookTitle": "听本_试音短篇",
  "bookSha256": "…",                       // 原文 UTF-8 的 SHA-256，用来对齐书架里那本
  "bookChars": 545,
  "language": "chinese",
  "chapters": [
    { "index": 0, "title": "第一章 试音", "charStart": 0, "charEnd": 545 }
  ],
  "segments": [
    {
      "id": "s0001",                       // 段内唯一、按序
      "chapter": 0,
      "charStart": 0,                      // 原文字符下标（含空白）
      "charEnd": 12,
      "text": "第一章 试音\n\n",           // 原文连续切片，一个字不改
      "speaker": "旁白",                   // canonical 名；别名在工厂侧合并掉
      "instruct": "平稳、清晰地念出章节标题，稍作停顿",  // 只写表演层
      "annotator": "yuanbao-sandbox",
      "confidence": 0.9
    }
  ],
  "notes": "身份层（音色描述）不在这里；由 App 调音台统一固定。"
}
```

## 3. 不变量（App 导入时逐条校验，4 道）

| # | 检查 | 失败怎么处理 |
|---|---|---|
| 1 | `schema == tingben.annotation/1` | 拒绝导入，提示版本 |
| 2 | `bookSha256` 与书架里那本书一致 | 拒绝，防张冠李戴 |
| 3 | `segments[].text` 顺序拼接 **逐字 == 原文** | 整份拒收，不静音不丢字 |
| 4 | `charStart/charEnd` 首尾相接、与 `text.length` 一致 | 整份拒收 |

**降级不是静音**：契约校验失败时 App 回退到「直接朗读」（按标点切句平读），
并在日志写 `ANNOTATION_IMPORT_REJECT` + 首因。逐字保真契约**没有放宽**，
只是把「谁来标」从手机挪到了沙盒。

## 4. 字段纪律

- `text` **不删归属语、不改标点、不补拟声词、不转繁简**。换行与空白都算原文。
- `speaker` 用 canonical 名（"林砚" 不写成 "年轻的林砚"）；别名合并在工厂侧做完。
- `instruct` **只写表演层**：意图/情绪+强度、节奏/重音、发声状态、停顿。
  **不许写音色身份词**（男声/低沉/沙哑/年轻…）——身份层归 App 调音台，
  写进来会和全局音色打架，又退回「每一小段音色都不一样」。
- 不写 `identity` / `voice` / `seed` / 采样参数：那些是本轮调音台的作用域。
- 不带音频、不带模型权重、不带外链，纯文本，离线可传。

## 5. 与 App 侧的作用域划分

| 谁 | 管什么 |
|---|---|
| 沙盒工厂 | 切句 / 说话人归属 / 别名 / 表演指令 / 逐字校验 |
| App 调音台 | 音色身份 12 维 / 9 个采样参数 / seed / 预设 / 可复现性 |
| App 制作准备页 | 仅本次：风格、语速倾向、情绪强度、段间静音、选章 |
| App 合成 | `text + 身份层 + 表演层` → `qt_synthesize(lang=chinese)` → WAV → 拼接 |

## 6. 示例

`听本_标注工厂示例.json` 是对 `听本_试音短篇.txt` 的一份真实产出：
27 段、3 个说话人（旁白 17 / 姑娘 6 / 林砚 4）、
`text` 拼接逐字相等、区间首尾相接、书指纹 `41955ff8…`。
