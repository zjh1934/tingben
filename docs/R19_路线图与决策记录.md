## 1. 六条决策（口头结论 → 项目口径）

### D1 · 音色是谁在选
**不是音频模型选，也不是纯随机。三层叠加：**

| 层 | 谁 | 内容 | 现状 |
|---|---|---|---|
| ① 身份层 | 用户（设置页）/ 角色表 | 固定音色描述，全书复用 | R19 前默认**留空 = 无锚点**，已修 |
| ② 角色风格层 | 角色→音色映射 | 可选，稳定表演习惯 | 有空壳，未接进起任务页 |
| ③ 本段情绪层 | 语言模型 4B | 只写「此刻怎么说」 | v2 提示词已禁身份词，权重会漏写 |

音频模型只按 `instruct + seed` 执行，**不挑角色、不挑音色**。

⚠️ **voice_design 的固有边界**：每次 `ttsSynthesize` 都按 instruct 重新采样音色，固定 seed(42) + 固定身份前缀能显著收敛，但**不能保证比特级一致**。要彻底根治得换 CustomVoice 权重用固定 speaker id —— 那是换模型 + 重下 2GB，不在本项目当前范围。**不许把「收敛」说成「根治」。**

### D2 · 语速 / 参数可调边界
- **已接出**：9 个采样参数（temp / top_k / top_p / rep penalty / seed / max_new_tokens / subtalker×3）、`instruct` 里的自然语言语速引导、**播放端**倍速（1 / 1.25 / 1.5 / 2x）。
- **物理上没有**：`qwen.h` 里这个 1.7B voicedesign 权重**没有** `speed` / `pitch` 独立字段，做不到「1.2 倍速合成」这种精确数值控制。播放端变速 ≠ 合成端变速，界面文案不许混淆。

### D3 · 并行合成判断
**结论：先做顺序流水线化，不做多实例并行。**

- 两个引擎不能同时驻留（LLM 2.5GB + TTS 2GB，8Gen3 必 OOM），现在是「全标完 → 释放 LLM → 再合成」，天然分两段。
- TTS 阶段开 2~3 路：qwentts.cpp 上下文非线程安全 → 多实例 = 多份 2GB；单实例排队省不了多少。手机大核有限，2 路常比 1 路慢（抢缓存 + 热降频）。
- 真正该省的：标完一块即写盘（已做）、合成完一块即写盘（已做）、WAV 合并从「全读完再拼」改流式追加（P2）。
- 真并行留到换小模型 / 大内存设备再说。

### D4 · 起任务前预设选项分级
按「便宜 → 贵」排，不一次全塞：

| 级 | 项 | 代价 |
|---|---|---|
| 零成本 | 朗读档位、段间静音、输出格式 WAV/M4A、失败块重做次数、合成前先试听第一块 | 配置/UI |
| 小成本 | 全局语速倾向、情绪强度上限、角色→音色映射接进起任务页 | 拼 instruct / 读表 |
| 中成本 | 按章预算、「到点停」时长上限、断点粒度（块/章） | 动 Producer |
| **别加** | 采样参数全展开、native 线程数、nBatch、seed 随机/固定切换 | 调试项，留设置页折叠区 |

### D5 · 界面：制作准备页（P1，下一轮）
**路径**：书架点书 → **制作准备页** → 点「开始」。起任务前给一页收齐选项，不散在设置页/制作页/进度页三处。

四块，默认只露第一块：
1. **做什么**：选章（全选/反选）、制作方式两档、预计块数（静态估算，不假装准）
2. **怎么读**（折叠）：朗读档位、全局音色描述、语速倾向、情绪强度、段间静音、角色映射入口
3. **怎么跑**（折叠）：失败重试、到点停、断点粒度、输出格式
4. **高级**（默认关）：采样参数、思考、线程/上下文 + 一行「一般不用改」

底部一个主按钮「开始制作」+ 小字「上次做到第 X 块，点继续」。**设置页只放跨书默认值，本书临时改动不写回全局。**

⚠️ 落地前必须列联动表：改 `Producer.start` 签名会连带 `TaskResume` 书签格式、`TaskCenterScreen` 续跑、`ProgressScreen` 进度重算、`hasCached` 分桶四处 —— 这是用户点名过的「改一处联动很多处」，单独一轮验，不和别的改动混。

**R19 过渡**：制作页先加一张**只读「本次配置」卡**（范围/方式/思考/声音），零签名改动、零联动风险。完整预设页 P1。

### D6 · 夜里跑任务 / 屏幕长亮 / 模拟点击
- **模拟点击：明确不做**。不提升进程优先级，Android 14+ 限制后台启动 Activity 与无障碍模拟点击，侧载可能被系统拦；LMK 回收时点击救不回来。
- **屏幕长亮**：用 `FLAG_KEEP_SCREEN_ON`（前台窗口，零权限、零风险），R19 已接，**仅任务 running 时**。夜里为保活而亮屏反而费电烧屏，不推荐。
- ⚠️ `FLAG_KEEP_SCREEN_ON` **不等于** WakeLock：屏幕灭了 CPU 仍会睡。
- **真正稳的路线**（见 `docs/后台保活与浮窗_调研.md`）：前台服务 `dataSync` + 可见通知 + 每块 `PARTIAL_WAKE_LOCK` + 电池优化白名单引导 + 逐块原子落盘。Android 15 起 FGS 约 6 小时超时，所以设计目标是**「到点停 + 回来点继续」**，不是「永不死」。
- 无障碍权限不是保活 API；悬浮窗不是前台服务。**两者都不做。**

## 3. 每轮纪律（用户反复点名，写进文件免得忘）

1. **别手搓** → 先翻本地 `reference/`，再联网找现成源码，最后才判断哪些真需要自己写；检查「最里层那块有没有真换」，不是「长得像不像」。
2. **改完先验证再打包** → 本地静态自检（括号 / 符号 / 残留 / 联动点）→ CI → 拆包硬验 → 发版。**一次多改几处再打一次包**，不要一改就打。
   - ⚠️ **R20 踩过的坑**：KDoc 注释里写 `KEY_*/DEFAULT_*`，`*/` 会**提前闭合块注释**，后面全变成顶层声明，编译器刷上百条 `Expecting a top level declaration`（run 27 失败）。本地静态自检要加一条「块注释内不得出现 `*/` 字面量」，括号计数抓不到这类错。
3. **改一处联动很多处** → 动签名/缓存键/状态机前先列表，逐个过；宁可拆成两轮，不夹在改文案的轮次里。
4. **如实说** → CI 全绿 ≠ 真机能用；文档结论 ≠ 真机验证；不把「收敛」包装成「根治」。
5. **git 通道被网关 403** → 走 REST 建 blob/tree/commit 更新 ref；`raw.githubusercontent.com` 在本环境被策略挡，核验走 blob API，用户手机不受影响。
   - ⚠️ **R19 踩过的坑**：脚本里用 `git ls-files` 取路径，中文文件名被 `core.quotePath` 转义成八进制，和远端真实路径对不上 → 误判成「远端多出来的文件」并生成删除条目，一度删掉 70 个文件。CI run 25 因结构自检缺文件立刻 failure，已强制回滚并重提。
   - **硬规矩**：路径一律用 `git -c core.quotePath=false ls-files`；**API 同步默认只做增量，绝不生成 `sha: null` 删除条目**；远端有而本地不在清单里的一律不动。
   - **R24 落地**：`scripts/sync_remote.py` 用 Git Trees API + `base_tree`，按 git blob sha 只传变化文件，逐文件核对后才更新 ref；中文路径不经过 `git ls-files`，从根上避开转义坑。
