## 批次 1b · 制作任务链诊断与自动续跑（本地已落地，待发版）

用户反馈：「合成一个音频后就停住，不会接着进下一批；关掉软件再打开，不知道任务是跑还是停，
希望队列里有在跑的任务就自动开始跑」。查完链路，真实状态如下。

**代码事实（不是猜测）**
1. `Producer.start` 一次只接一本书 + 一组 `onlyChapters`，`run()` 把这些章的所有段
   **拼成一个 WAV** 后注册一条成品，然后 `_state = "完成"` 就停。全工程没有任务队列，
   也没有「做完后自动接下一个」的调度器。所以「愣住、不知道后面进哪张」是真实缺口。
2. `TingbenApp.onCreate → Producer.restore()` 把 `running` 改成 `interrupted`，
   状态文案明确写「点「继续制作」接着做」；`ProduceService` 是 `START_NOT_STICKY`，
   进程被杀后系统不会重启服务。**打开软件一定是静止等待手动点**，既不跑也不说清在等什么。
3. 顺带查出一个真缺陷：`Producer.stop()` 只把 stopped 写进文件，没同步内存里的 `current`；
   `finally` 会按 `running` 再标一次 `interrupted`。结果用户主动停止的任务，
   下次开软件会被当成崩溃中断。自动续跑上线前必须先修，否则违背用户意图。
4. 批次 1 改了 TXT 切章规则，旧任务按旧章号存 `only`；`realProgress` 现在按新规则重算，
   旧任务直接续跑会把断点对错章。自动续跑必须能识别旧口径。

**本轮本地落地**
- 修 `stop()`：同步回写 `current = stopped`，finally 不再误标 interrupted
- `finally` 保留真实失败 stage（没完成 / 出错了 / 已停止），供守卫区分
- `TaskInfo` 加 `splitRule`，`TaskResume.SPLIT_RULE = 2`；旧记录缺省为 1，不自动续跑
- 新增 `TaskResume.autoResumeBlockReason` 与 `Producer.autoResume`：
  只放行「进程被杀 / 崩溃」留下的 interrupted 任务；手动停止、失败、旧切章口径、
  书被删、模型没齐、调音改过一律不自动跑，并给出可见原因
- 触发点放在 `App()` 的 `LaunchedEffect(Unit)`（Activity 可见之后），
  **不在 `Application.onCreate`**，避开 Android 12+ 后台启动前台服务限制
- 新增 `scripts/r127_verify.py` 并挂 CI，正向 23 条 / 旧形态 2 条 / 反向注入 13 例全拦下

**本轮不做（留给下一批次）**：任务队列调度器。理由见下。

### 下一批次的设计口径（工程判断，已按纠正后的来）

保留「一次任务 = 一本书 + 选中章 → 一个合并 WAV」的现状，**不改成每章出一个音频**：
那样会动 `AudioLibrary` 索引、章起点 JSON、断点指纹，牵连整条播放与续跑链，
且与后面的播放器统一耦合，改错代价太大。

队列 = 多本书 / 多批选中章的待做列表，复用现成的 `tasks.json`，加 `queued` 状态：
- 一个 `done` 之后调度器自动 `start` 下一个，不再停在「做好了」
- 界面明确「队列 N 个 · 正在第 M 个 · 做完后自动接下一个」，把「愣住」变成有反馈
- 调度器复用本轮同一套守卫，守卫不过就停队列并说清原因，不无限重试
- 用户点停止 = 暂停整个队列，不是只停当前一个，避免停了又自动跑下一个
- 失败（存储不足 / 引擎报错）即停队列并高亮，不自动跳过

**验证边界**：沙盒无 Android SDK，本轮未真编译；自动续跑与前台服务的实际时序、
旧任务守卫在真机上的表现，都要等出包后上手确认。

## 批次 1c · 分段看台灰格状态重建（本地已落地，待发版）

用户反馈：「生成这一章时看台已经切块成很多小节，未合成的灰色小块本来有显示；
把页面切出去再回来，灰格就不在了，已合成的还在，然后一块一块往出蹦；
但继续合成仍按原顺序继续。」

**诊断结论：不是合成链路断了，恰恰相反，磁盘链路是好的。**
用户那句「继续合成还能按原来顺序」就是证据——分段计划、断点、逐段落盘都没丢。
坏的是**看台列表的数据源**：`ProgressScreen` 里 `segs` 有两个互斥来源。

| 来源 | 内容 | 何时生效 |
|---|---|---|
| `fallbackSegs`（`Workbench.segments`） | 计划段全量，含未合成的灰格 | `treeChapter == null`，进页面瞬间 |
| `chapterRows`（`AudioTree.load` 的 `ch.segments`） | **只有已落盘的小块** | `LaunchedEffect` 异步加载完 `treeChapter` 之后 |

`treeChapter` 是异步赋值，页面生命周期内两个来源发生切换：
先看全段（灰+绿）→ 加载完只剩已合成的 → 之后每合成一段 `st.done` 变化、
`LaunchedEffect` 重跑、树里多一条，UI 就多一个格子。
「切出去再回来」把 `remember` 重建，把这个切换暴露得更明显。
音频树里根本没有「还没合成」的段，拿它当列表来源，灰格必然整片不存在。

**本轮本地落地**
- `ProgressScreen`：`plannedSegs` 做唯一骨架，段数恒定；
  `treeWav` 只按 `seq - 1` 给对应段补 `wav`，决定绿/灰，不决定列表长度；
  `index` 统一重编号。删除 `chapterRows` 直接当 `segs` 的分支。
- 连带修正：章视角进度条分母原来是「已登记小块数」，随合成一起涨，
  百分比失真；改后分母固定为计划段数，进度才真实。
- `Workbench.segments`：去掉 `mapped.take(60)` 与 `coerceAtMost(59)` 硬砍
  （用户说「很多个小块」，超过 60 就显示不全）；兜底分支只留 2000 的极端保险。
- `r119_verify.py` 两条绑死旧形态的断言语义化；新增 `r128_verify.py` 挂 CI，
  正向 11 条 / 旧形态 5 条 / 反向注入 12 例全拦下。

**顺带查出、本轮不动**
`SegPlan.writeMap` 全工程没有调用点，`readMap` 恒为 null，
看台实际一直走 `Workbench.segments` 的兜底推算分支（按 `t.total` + 已落盘最大序号）。
启用 segmap 会改变续跑指纹口径，牵连 `realProgress`，不在这轮动，排到后续。

**验证边界**：沙盒无 Android SDK，本轮未真编译；
「切出去 / 切回来」在真机上是 Activity 重建还是仅重组、异步树加载的时序，
都还没上手确认。段数极多时看台用 `Column + chunked(8)` 全量渲染会变重，也待真机验。

## 批次 4 · 统一播放器 / 两态隔离 / 真图标（本地已落地，待发版）

用户原话要点：「应该要做一个统一的音频播放器，不管从目录进还是从音频管理进」、
「底部常驻一个播放器，点那一条条幅，点开就是播放器」、
「播放暂停上一个下一个都是用字符的，要用代码画出来的真图标」、
「制作中的一小段音频是不进播放页的，这个得花心思设计」、
「音频文件东一块西一块很混乱，要集中设计」。

**诊断：「东一块西一块」是真的**
`PlayQueue` 本来就是单一状态源，但它把三类来源混进同一个队列：
① 整章/整本成品（chapter / chapterMerged）② 制作中的小段 WAV（queueId = "seg"）
③ 调音台试听（"trial"）。
结果点一下看台格子，通知栏就弹「正在播放 第 N 段」、底部常驻条也跟着变成小段，
上一/下一/目录按钮全指着一段几秒的试听 —— 这就是混乱的根源，不是缺播放器页。

**本轮落地**
- **两态隔离**：`PlaybackState` 加 `preview` 字段，PlayQueue 内部按 queueId 判定
  （`"seg"` / `"trial"` 为临时试听态）。调用点一个没改：
  小段试听不占常驻条、不进全屏播放器页、不进通知栏；看台格子仍就地播停。
  `PlayNotif` 双保险跳过 preview。
- **统一播放器页 `PlayerSheet.kt`**：点底部常驻条任意位置展开全屏浮层；
  收起 / 关闭 / 上一 / 播放暂停 / 下一 / 目录 全在里面；
  可拖动进度条、时间、五档倍速、选章列表（从常驻条弹窗搬来，全 App 只此一份）。
  用**全屏浮层**而不是新增 Screen 枚举值 —— 它不是「另一页」，是同一份状态的展开视图，
  也避免把刚收敛好的 8 值导航再撑回 9 值。
- **通知栏怎么用才好**：播放控制通知主体点击带 `open_player` extra，
  回软件直接展开播放器页，不再停在书架猜「刚才播到哪」；
  通知动作（上一段/暂停/下一段/关闭）仍走 `PlaybackActions`，与页面共用同一状态。
- **真图标 `PlayIcons.kt`**：`IconPlayPause / IconSkip / IconClose / IconChevronDown / IconQueue`
  五个图标全部 Canvas + Path + Stroke 代码绘制，随主题取色、任意尺寸不糊；
  常驻条与播放器页的「‹ ⏸ ▶ › × ⋯」字符清零。
  制作任务页的「⏸ / ▶」是**停止/继续制作**，语义不同，保留不动。
- 删掉 MiniPlayBar 里重复的选章弹窗，选章集中到播放器页；
  `r103 / r111` 里跟着搬家的断言语义化，新增 `r133_verify.py` 挂 CI。

**一处如实保留的边界**

所以点试听会暂时代替主队列（这是原有行为，不是本轮引入）。
