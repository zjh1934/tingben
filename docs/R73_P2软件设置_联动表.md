**关键技术选择**：颜色常量改成**普通 getter**（`private val Bg: Color get() = palette.bg`），
getter 内读取 `mutableStateOf` 顶层状态；Compose snapshot 会在组合期跟踪它，切换主题即重组，
**所有 22 个调用点一行都不用改**，也不依赖 `@Composable get()` 这种编译器特性。
比逐处替换成 `MaterialTheme.colorScheme.*` 风险低得多。

## 5. 已知限制（如实说，不藏）

- 状态栏图标：加 `values-night` 只覆盖「跟随系统且系统夜间」；用户**强制深色但系统仍浅色**时图标颜色由运行时 `WindowInsetsController` 修正，若该 API 在本 BOM 不可用则退化为已知瑕疵，写进落地报告，不宣称完美。
- `MaterialTheme` 包裹会让未显式着色的 M3 组件（Switch 轨道、Button 默认态）跟随配色，和自定义色板可能有轻微色差，属观感问题不是功能问题。
- 真机零证据；按新纪律不向用户索取装机验证。
