# R36 · 研究回来的想法（源码读进上下文后）

> 用户要求「去借别人的项目、不是简单替换代码」，且「研究回来的应该是进上下文的」。
> 本轮把现成件源码/索引页逐行读进来后，得下面这些判断，再定核心代码，不是先写再找依据。

## 1. 别人的参数面板不是「一张大表单」

- text-generation-webui 把生成参数塞进 `Parameters → Generation` 两个 Tab，用 Row/Column 再切成
  `Curve shape / Curve cutoff` 等小组，顶部是一条 **preset_menu + 保存 / 删除 / Restore** 工具条。
  预设存 `user_data/presets/*.yaml`，可以手改、导入导出。它不是把 20 个滑块平铺，
  而是「先选一套预设，再只动少数几项」[citation:8][citation:9]。
- Qwen3-TTS 的第三方 WebUI 把「模型与生成参数设置」做成**页面顶部的可折叠面板**，
  里面才有 `max_new_tokens / Temperature / 精度 / 设备`；主操作区只留文本、语言、音色、指令 [citation:6]。
- ebook2audiobook 的 `--help` 把 `temperature / top_k / top_p / repetition_penalty / speed / text_temp / waveform_temp`
  列成一整组可覆盖参数，说明这类引擎「能控的」就该成组列出，不该埋在折叠深处 [citation:17]。

**结论**：调音台要的是「顶部一条只读总览 + 若干可折叠组 + 预设工具条」，不是 5 张卡一路往下堆。

## 2. 预设必须能由用户产生，且要能覆盖

IndexTTS WebUI 的 `presets.py` 给了完整范式：每个预设一份 `preset.json`、带 `PRESET_VERSION`、
名字先 `safe_preset_name` 清洗、`list / save / load / delete / exists` 五个函数、
Session 里「存为预设（同名覆盖）」；新建 Session 时先选预设 [citation:11][citation:15]。
text-generation-webui 则给了工具条形状：下拉选、💾 存、🗑 删、Restore 回默认 [citation:8]。

**结论**：预设不是编译期常量表。本轮 `MixerPresets.kt` 把 4 组内置留着当基准，
用户存的全部落 `mixer_presets.json`，同名覆盖、可删、坏条目跳过、`.part` 原子落盘。
这是「我也可以自定义加预设」最直接的实现，不需要新框架。

## 3. 折叠是状态问题，不是动画问题

ProAndroidDev 的 `ExpandableSection` 把 `isExpanded` 放进 `rememberSaveable`，
强调「configuration change 与 recomposition 都保留」，内容才用 `AnimatedVisibility` 包 [citation:10]。
OfflineLLM 的 `SettingsScreen.kt` 本地源码里也是 `rememberSaveable` 管理展开态。

**结论**：我们抄「状态提升 + 记住展开态」这层就够；`compose.animation` 不在依赖里，
为一个淡入动画加依赖不划算，用 `if(open)` 呈现，零新增 Gradle 依赖。

## 4. 「能控的通通都要控」= 先有一张覆盖核对表

PocketPal 的 `CompletionSettings.tsx` 是按 `COMPLETION_PARAMS_METADATA` 逐项生成控件，
连 `n_predict` 这种整数项都单独成控件，并提供「回到 server default」[citation:8]。
对照我们：9 项采样里 `max_new_tokens` 只在设置页、调音台漏了；12 维只是 12 行说明文字，
根本不能逐维选；表演层 5 项在调音台只读；拟声 / 角色映射开关只在设置页。

**结论**：`Mixer.coverage()` 先把 30 项可编辑、5 项只读、5 项结构不可控列成一张表，
界面逐项给出控件，表本身也显示在「合成边界与覆盖核对」组里，用户能自己核对有没有漏。
结构不可控的（量化档、权重模式、speaker 表、`speed`/`pitch` 数值字段、行内标签）
明确写「结构」，**不画假开关**——`qt_tts_params` 里物理上没有这些字段。

## 5. 角色预设空，是「没给初始卡」不是「没做角色系统」

`VoiceCast` 早就有 `cast.json` 原子落盘、别名、`USER_LOCKED`（抄 ReaderVoice `CharacterProfileStore.kt`），
但它的 `collect()` 靠扫已落盘标注，一本书没标过就是空表。IndexTTS WebUI 的做法是
「samples/ 下按角色建文件夹、旁白/路人勾匿名角色」，先给一套可改的初始卡 [citation:14]。

**结论**：不重写角色系统，只加 `CastPresets.seedIfEmpty()`：4 张内置卡（旁白 / 青年男主 /
青年女主 / 长者）用现成音色网格 `P21/P02/P06/P03` 的描述填 `description`，
只在「从没 seed 过 + 表为空」时写一次，绝不覆盖用户后来改的表。
seed 会改 `VoiceCast.hash` ⇒ 旧 WAV 按 R14 既有机制作废，这是预期，不是回归。

## 6. 作用域比参数本身更容易出事

用户上一轮骂过「哪些长期有效、哪些仅这一轮，没分开」。所以：
- 音色 12 维、9 项采样、拟声、角色映射、角色卡、预设库 = **跨书长期默认**（`Prefs`）
- 表演层 5 项 = **以后新建任务的默认**（`Prefs.defaultPerf`），正在跑的任务不回写
- 制作准备页 = **仅本次**，续跑读 `TaskInfo` 书签

这三层只共用一份真值源，不各存一份 `TtsKnobs`。续跑路径刻意不动，否则新默认会污染旧任务。

## 7. 官方能力边界（没有因为改 UI 就变）

VoiceDesign 是「用自然语言描述造声」；CustomVoice 才有 9 个预置 speaker；
WebUI 的 `max_new_tokens / Temperature` 是生成参数，不是音色参数 [citation:5][citation:7]。
官方中文样例强调描述越具体越稳，Alexandria 的 40 组对照说「先写声学物理目标」胜过纯情绪人设——
这正是 12 维逐维可编辑、且顺序按 Anatomy-First 拼的依据。

## 8. 不做的

换模型、4B 标注撤主路、系统 TTS、无障碍/浮窗/并行合成、为折叠动画加依赖、
把 `AnimatedVisibility` 或 `material-icons-extended` 塞进 Gradle、AGPL 源码复制进仓库。
本轮只重排音频模型的控制台，4B 那侧一行未动。

> ⚠️ 所有「更好用」都是设计与文档结论，真机 24117RK2CC 上仍零证据。
