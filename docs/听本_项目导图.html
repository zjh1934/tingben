② 四层移植 · 扒谁、抄什么、加工成什么

不是整包微调：四个项目分处 PC Python / Rust CLI / Android 聊天 App / Android 阅读器，没有一个能直接装。按层扒核心，再串成一条链。

OfflineLLM
Apache-2.0 · Android 底座
✓无 INTERNET 权限的 Manifest
✓仅 arm64-v8a + largeHeap
✓SAF 导入任意 GGUF
✓llama.cpp JNI 生命周期 / 版本目录
✓thinking 标签剥离
↓ 加工
工程骨架：Gradle / Manifest / JNI 胶水 / 模型导入
Alexandria
MIT · PC Python · 标注契约
✓speaker / text / instruct 三段 JSON
✓500 字同角色合并分块
✓角色表 + 最近 3 条跨块上下文
✓JSON 修复四级降级
✓复核 pass（我们关掉，它会改字）
↓ 加工
中文 prompt + 字符级逐字 gate（Alexandria 没有，我们加）
Antioch
MIT · Rust CLI · 引擎组合
✓llama.cpp + qwentts.cpp 同栈
✓逐块 WAV，写完立即落盘
✓重跑跳过已完成块（断点）
✓WAV 拼接 / 章节样本数
✓两 ggml 共享符号的踩坑记录
↓ 加工
合成队列 + checkpoint.json + WAV 合并器
ReaderVoice-Mobile
Android · 产品不变量
✓原文永不修改，只建 source map
✓UNKNOWN 合法，禁止强造角色名
✓播放窗口优先于未来生成
✓进程被杀只丢当前批
✓「能跑」≠「通过」，最终 PCM Gate
↓ 加工
状态机 + 不变量测试 + 5 页信息架构
四层汇入 → 自己只剩：Kotlin 编排 + CI + 中文 prompt + 逐字 gate + 5 页 UI

③ 数据流水线 · 串起来之后长这样

txt ──SAF持久URI──▶ ChapterSplitter（章节 / 500字 / [start,end) 偏移） │ ├─ 标注阶段（只加载 LLM，llama.cpp JNI） │ prompt_zh.txt + 角色表 + 最近3条 ──▶ Qwen3-4B ──▶ JSON[] │ ├─ JSON 修复四级 │ └─ 逐字 gate：concat(text) == 本块原文 ? │ ├─ 是 ─▶ 写入 annotations.jsonl │ └─ 否 ─▶ 重试1次 ─▶ 仍否 ─▶ 降级直读（原文照读，不静音） │ ├─ llmFree → ttsLoad（两个模型串行，绝不同时常驻） │ ├─ 合成阶段（qwentts.cpp JNI，24kHz 单声道 PCM） │ 每块 ─▶ chunk_NNNN.wav（原子落盘）──▶ checkpoint.json │ ├─ 合并：按序号拼 PCM + 重写 WAV 头 + chapters.json │ └─ 播放 / 导出 ──▶ 我的音频
旧项目真机事故带走的一条：两个上游各产一套 libggml*.so，同名互相覆盖 → dlopen failed: ggml_top_k_mask。新工程只保留 llama.cpp 那一套 ggml，libqwen.so 共用；CI 做 UND 符号差集自检，不给「编译成功」盖章就发包的假绿留门。

⑤ 交付闸门 · 没过就不算做完

G1 · 代码同步新仓库 main 分支有全部源码，旧仓库一行不动

G3 · APK 合规无 INTERNET / 无 .gguf / 仅 arm64 / <100MB / 固定签名
G4 · 公开直链浏览器直接下，覆盖安装不卸载
G5 · 逐字保真100 段模型输出拼接 == 原文（单测）
G6 · 真机出声导入书 → 点一次 → 能听（只有你能验）
如实说：G5 我能用单测证明，G6 只有你在真机上点过才算。沙盒没有 kotlinc/gradle/ndk，编译只能走 GitHub Actions；「编译通过」永远不等于「真机能用」。
