# 01 · 从零起步总纲

> 回答三个问题：AI 做安卓软件从零要什么 / 我做什么 / 你做什么、配套什么。
> 依据：`docs/调研_从零做安卓端侧AI应用.md`（20 条来源，含不确定项标注）。

## 一、AI 做安卓软件，从零到底需要什么

**结论：不一定需要一台装了 Android Studio 的电脑，但必须有一条可信的构建线。**
本沙盒实测：有 `java` / `git` / `python3`，**没有** `kotlinc` / `gradle` / `ndk-build` / `cmake` / `adb` / `sdkmanager`。
所以「代码我写、编译交给 GitHub Actions、包你下」不是权宜之计，是本项目的正式架构。

### 必须现在就有（锁死，不漂移）

| 层 | 锁定值 | 谁提供 |
|---|---|---|
| JDK | 17 | CI 镜像 |
| AGP / Gradle | 8.13.x / 8.13.x（成对验证） | `gradle/libs.versions.toml` |
| Kotlin | 2.2.x（**建议值，非官方支持声明**，以干净 CI 构建为准） | 版本目录 |
| compileSdk / targetSdk | 36 / 36（Android 16 硬前提） | `build.gradle.kts` |
| minSdk | 28（待拍板，见 §5） | 同上 |
| NDK / CMake | r28 固定小版本 / 3.22.1 | CI 安装 |
| ABI | 仅 `arm64-v8a` | Gradle |
| 签名 | 一次性 keystore，离线保管；口令进 Actions Secrets | **你生成，我写校验** |
| 引擎 | llama.cpp + qwentts.cpp，**锁 commit 的 submodule / vendored**，两个 JNI 模块静态隔离、隐藏内部 ggml 符号 | 我写 CMake/JNI |
| CI | 一个 `ubuntu-latest` job：检出 → 锁版本 → 原生交叉编译 → 单元测试 → assemble → 校验（无 INTERNET / ≤100MB / 无 `.gguf`）→ 签名 → 上传 artifact 与报告 | 我写 workflow |
| 发布 | 公开仓库固定直链 / `releases/latest`，保留旧版下载位 | 我写脚本 |

**为什么仍是 llama.cpp 直连**：两个定稿权重都是标准 GGUF，MNN 要 `gguf2mnn.py` 转换、ExecuTorch 明确不能可靠吃 GGUF、MediaPipe 只认有限官方模型。直连是唯一不要求你重下或转格式的路径。调研报告 §3 有完整对照。

**两个 ggml 不能各编一份导出全局符号**：旧项目就是在真机上撞过 `dlopen failed` 后靠「只留一份共用」才修好。新项目从第一天就按**命名空间隔离**做，不靠事后补丁。

## 二、我（AI）全程做什么

1. 冻结契约与状态机，写字符级正文回溯测试（**先写测试，再写界面**）
2. 版本目录、Gradle、CMake、JNI 胶水、两个引擎的锁版本接入
3. 模型清单与导入校验、`.part` 原子落盘、SHA256、失败原因码
4. 逐章检查点、原子写入、被杀后恢复、前台服务与持续通知
5. PCM → MediaCodec AAC → MP4/M4A，音频焦点与播放通知
6. L0~L3 分层日志、两步确认的诊断包（默认脱敏）
7. CI workflow、构建报告回写、APK 发布脚本、每轮自检
8. 文档、决策记录、每轮「做了什么 / 没验证什么」

**我永远不能说「我在真机上验证过了」。** 我能给的只有：编译通过、文档支持、风险推定、自检数据。

## 三、你（用户）必须亲自做什么

| 阶段 | 你做 | 验收标准 |
|---|---|---|
| 0 | 拍板 §5 的口径 | 一句话即可 |
| 1 | 生成并离线保管签名 keystore；确认新仓库名 | 密钥不进仓库 |
| 2 | 三个 GGUF 已下好（**你手上已经有了，不用重下**） | 文件名/尺寸与清单一致 |
| 3 | 浏览器下载 APK，覆盖安装 | 签名一致、不卸载 |
| 4 | 导入一本书 → 点一次「开始制作」→ 等出声 | 能听 |
| 5 | 飞行模式下跑一次、杀进程重开一次 | 无网络请求、从断点续 |
| 6 | 出问题时「复制诊断信息」贴我 | 我能定位 |

**你不需要**：懂 GGUF、懂 JNI、懂 Gradle、看日志里的技术词、按 ①②③ 手动摆流程。

## 四、配套什么（缺一不可）

- 两个 GitHub 仓库：私有源码仓 + 公开 APK 仓（本轮已建）
- 一份签名 keystore + Actions Secrets（**只有你能给**）
- 锁 commit 的两个上游引擎源码
- 模型清单与校验值（`contracts/model-manifest.json`）
- 一份「失败即停」的 CI 闸门：无网络权限、无权重、体积、ABI、签名
- 真机一台（Xiaomi 24117RK2CC / Android 16）

**不需要**：Android Studio、本地 SDK/NDK、代理下载器、云端 GPU、任何付费服务。

## 五、首批要你拍板的口径（每题都给了建议默认）

| # | 问题 | 我的建议默认 | 影响 |
|---|---|---|---|
| 1 | 首版导入格式 | **只 `.txt`**，epub/md 放二期 | 调研强烈建议：把格式解析从主路摘掉，先把「可靠」做完。你之前要 epub，所以这条**等你点头** |
| 2 | 思考外显 | 默认**关**，设置里可开 | 可开关模型，开了每块先吐推理、明显更慢 |
| 3 | 多角色换声 | 首版**单音色**（你手上的 voicedesign） | 物理限制，换 customvoice 要重下 2GB |
| 4 | 导出格式 | 首版**只 M4A**，WAV/m4b 二期 | 少一条编码链，先把「能听」跑通 |
| 5 | 后台续跑 | 首版**要**（常驻通知 + 断点恢复） | Android 15/16 有 6 小时前台配额，只能「暂停后点继续」 |
| 6 | 名字 / 仓库 | **听本** / `tingben-android` + `tingben-apk` | 想换说一句，一条命令改 |

回「按默认」也行，只挑有意见的编号回也行。

## 六、阶段闸门（每道没过就不进下一道）

```
PR-0 契约与测试        ← 本轮位置
PR-1 空项目 + 签名 + CI + 无权限校验
PR-2 .txt 导入 + 持久 URI
PR-3 llama.cpp JNI + 正文回溯测试
PR-4 模型清单/校验/失败码
PR-5 标注输出 + 三道 gate
PR-6 qwentts.cpp JNI + PCM 播放
PR-7 PCM→AAC→MP4
PR-8 检查点与恢复
PR-9 L0/L1 用户界面（最后才做界面）
PR-10 首个内部签名版
```

**注意 PR-9 排在倒数第二**：界面不是第一件事，是契约、链路、可靠性都成立之后才做的最后一层皮。旧项目恰恰反过来，所以做成了调试台。

每道闸门的机械验收：CI 干净通过 / 100 段模型输出拼接等于原文 / 强杀后恢复误差 ≤ 1 个已完成片段 / 飞行模式无网络请求 / APK < 100MB / 覆盖安装签名不变。
这些是**验收闸门，不是性能承诺** —— 真机 RTF、峰值内存、热降频目前全是空白。
