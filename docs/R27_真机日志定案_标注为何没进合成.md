# R27 · 真机日志定案：模型到底标了没有，为什么声音里听不出来

> 2026-11-04，依据用户 `1.0.0+32` 两张真机截图（进度页 / 诊断页）与本地源码逐行核对。
> 本轮只回答「A / B / C 哪个」，并修掉已被证实的口径与采纳断点。不预设「角色飘」，那要等真听过成品再判。

## 一、用户问的三选一，判定如下

| 猜想 | 判定 | 证据 |
|---|---|---|
| A 模型真的没有产出 | ❌ 否 | 原始产出 896 字、有效 JSON 候选 877 字、非 JSON 仅 2%；9 条规则里 7 条 PASS（纯 JSON 数组、无尾文、无行内标签、不写音色身份、条数、speaker、instruct 全过）。它规规矩矩吐了一个 JSON 数组并被解析成条目。 |
| B 产出没有介入下一步 | ✅ 是（主因） | 「一条没采纳（整块直读）1」「降级直读 1」「失败码 CONCAT_LEN_MISMATCH×1」：`Adoption.adopt` 在**第一条**就 break，kept=0 → `FALLBACK` → `Annotator.fallback(chunk)` 用 `directSegments` 整块覆盖 → 全部 `旁白 / 平稳、清晰地叙述，句间自然停顿` 进 TTS。模型产出只留在 rawdump 与审计里。 |
| C 显示口径的原因 | ✅ 也是 | 进度页、看台、诊断摘要三处都把不同对象混成一句话，见第三节。 |

**一句话**：模型认真标了，程序没要。你听到的「不标注也不错」= 标注档失败后降级直读 vs 直接朗读，本质是 A vs A，不是「标注 vs 不标注」。

## 二、根因链（代码级）

试音短篇第 1 块原文以 `第一章 试音\n\n雨下了一整夜…` 开头。模型把章节标题/空行当元信息跳过，`text` 从正文第一句开始：

1. `Annotator.ruleChecks`（Pipeline.kt 345 行起）旧版 `original.indexOf(a.text, cursor) != cursor` 要求**第一条必须等于原文第 0 个字符**：
   - 于是 `VERBATIM 0/1`、`ORDERED_SUBSTRING 0/1`，而其余 7 条全 `1/1` —— 这个「7 过 2 不过」的形状正好排除「模型摆烂/吐废话」，指向「少了前导标题」。
2. `Adoption.adopt`（R24 从 Antioch 移植）旧版 `original.regionMatches(cursor, a.text, ...)` 同样要求严格前缀 → 首条 `NOT_PREFIX_AT_0` → `break` → `kept=0` → `disposition=FALLBACK`。
3. Pipeline 1066 行 `result = Annotator.fallback(chunk)`，`gateFails++`。此后 `ANN_CONTENT` 里全是〈程序补齐〉，TTS 收到的是平读段。
4. 失败码走到 `CONCAT_LEN_MISMATCH` 分支（1006 行旧码）。**这个名字是错的**：它不代表长度不符，而是「逐条采纳 0 条」。截图里「原文 358 / 标注 text 358 / 差 +0」正好把人往长度问题上带。

> 推断（未拿到该次 `ANN_ADOPT_DETAIL` 全文，标为推断而非实测）：首条 text 与原文开头不符，最可能是跳过章节标题。若模型其实是**改写正文**（text 根本不是原文子串），本轮的缺口补齐救不了，摘要里的「未采纳首因」会显示 `NOT_FOUND_AFTER_0`，下一轮据此再定。

## 三、三处显示口径混用（这就是「流程页说没加工、日志说有加工」）

| 位置 | 旧口径 | 实际对象 |
|---|---|---|
| 进度页 `已标注 1/2 块` / `50%` | `emit(..., done=i+1)` 无条件写 | 只表示「跑完 1 块」，降级直读也算标了；`1 块直接续上` 是磁盘缓存命中，不是新标注 |
| 分段看台蓝格 `已标注` | `annotated = annFile.exists()` | 只看有没有 `ann_*.json`，文件内容全是直读段也照样蓝 |
| 诊断摘要「长度」行 | `textChars / lenDelta / firstDiff` 取 `finalAnns`（**最终直读段**）；「规则生效」取 `parsed`（**模型候选**） | 两套对象并排 → 出现「差 +0」却「逐字保真 0/1」的自相矛盾 |

## 四、本轮改了什么（6 个 Kotlin 文件 + 自检脚本）

1. **采纳链路**（`Adoption.kt`）：严格前缀 → **有序子串 + 缺口补齐**。模型跳过的标题/空行由 `TextSplitter` 按标点补成旁白段，顺序、不重叠、拼回逐字相等仍由 `gate` 保证，**逐字契约一字未放宽**。这是向 Antioch「结构归确定性代码」的原意靠拢，不是手搓新算法。
2. **逐条来源**（`Adoption.kt` / `Pipeline.kt`）：`Result.srcModel: List<Boolean>`，缺口段 / 模型段 / 尾部补齐段各自标记。`contentJson` / `contentLines` 不再用「前 kept 条」猜来源，避免把程序补的标题误标成〈模型标注〉。
3. **规则判定**（`Pipeline.kt`）：`ORDERED_SUBSTRING` 同步允许缺口；`VERBATIM` 保留「模型有没有逐字覆盖整块」的真实 0/1；中文名改成能区分两者的写法。
4. **进度文案**：`已完成 X/Y 块 · 模型真标注 a 块 · 改走直读 b 块 · 磁盘续上 c 块（旧缓存未记来源）`，不再出现无条件「已标注」。
5. **看台来源 flag**：每块写 `ann_%04d.src`（`MODEL` / `FILL`），小格 绿=有声音 / 蓝=模型真标注 / 黄=模型未采纳按原文直读 / 灰=没轮到或旧缓存未记来源。展开时明说「模型产出没被采纳，按原文直读」。
6. **审计摘要**：拆成「模型候选」与「最终进 TTS」两段各标对象；新增「未采纳首因」「模型产出未被采纳 N 块」「最终逐字相等 N/N」；旧失败码映射成「采纳0条(旧码)」；`BlockAudit` 加 `adoptFirstDrop` / `finalVerbatim`，兼容旧 jsonl。

没动：`prompt_zh.txt` v2、native、`Producer.start` 签名、`bucket()` 缓存分桶、TTS 调用、前台服务（P1② 已在 +34 落地）。

## 六、真机仍待核

本轮改的是「让合规产出能进 TTS」与「显示不再骗人」，**不是宣称声音变好听**。装 `1.0.0+35` 后跑一次试音短篇，贴诊断摘要看三处：
