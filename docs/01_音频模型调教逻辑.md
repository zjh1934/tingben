# 01 · 音频模型调教逻辑

> 调音台重做的**事实边界**。依据顺序：随包 `app/src/main/cpp/qwen.h`（一手，APK 里真编译的那份）
> → 官方模型卡与官方 Python API → 第三方 GGUF 仓库交叉验证。界面画法不在此定，每轮自己查同类软件再做。

## 0 · 四类输入不是同一类东西

- **「系统提示词」不属于音频模型**：那是文本模型时代写逐段 JSON 的契约，音频模型没有这个字段。
- **音色描述 / 自定义语气**：不是两个旋钮，**是同一条 `instruct` 字符串的两段**。
- **9 项可调参数**：另一组独立数值字段，和 `instruct` **同时生效、互不覆盖**。
- **参考音频**：不是互斥开关，是**另一份 talker 主权重**才有的输入（base 模式）。

把四样摆成一排平级控件，层级没分开，就会怎么调都像碰运气。

## 1 · 三份模式主文件的字段边界（`qwen.h` 268–356 行）

模式不是界面开关决定的，是 `qt_init` 从 talker GGUF 读 `model_type`，`qt_synthesize` 按规则强制校验，
不合规直接 `QT_STATUS_MODE_INVALID`：

| 输入 | voice_design | custom_voice | base |
|---|---|---|---|
| `text`（要念的正文） | 必填非空 | 必填非空 | 必填非空 |
| `instruct`（造声/风格指令） | **必填** | 可选 | **拒绝** |
| `speaker`（预设音色编号） | 拒绝 | **可用** | 拒绝 |
| `ref_audio_24k` / `ref_text` / `ref_spk_emb` / `ref_codes` | 拒绝 | 拒绝 | **可用**（克隆） |

- 注释原文「Rejected for custom_voice / voice_design」；参考音频与 `speaker` 互斥 [qwen.h:294-298, 344-351, 402-403]。
- `ttsSpeakers()` 对 base / voice_design 返回 0 [qwen.h:384-385]；我们 `speaker` 在 voicedesign 下恒传 `null`。
- 采样 9 项，主 talker 抽 c0、sub-talker 抽声学码，各自独立一套：
  `seed / max_new_tokens / temperature / top_k / top_p / repetition_penalty / subtalker_temperature / subtalker_top_k / subtalker_top_p` [qwen.h:303-320]。
  `seed = -1` 交引擎硬件随机；`temperature = 0` 走 argmax；`top_k <= 0` / `top_p >= 1` 关闭对应截断。
- **口径冲突**：第三方 GGUF 仓库把 `base` 写成「指定说话人零样本 TTS」、`customvoice` 写成「参考音频克隆」，
  与官方模型表正好反过来。**以随包 `qwen.h` 为准**。

## 2 · 官方能力对应

- 1.7B-VoiceDesign：按自然语言描述造音色，指令控制 ✅；GGUF 仅 1.7B 档有，两个文件必须成对加载。
  官方 API 把「想要什么嗓子」放在 `instruct` 里，落到 GGUF 引擎就是 `qt_tts_params.instruct` 一个槽位。
- CustomVoice：9 个精品音色 + 风格指令。
- Base：3 秒参考音频克隆，需 `qt_extract_voice_ref()`。

**当前状态**：三份主文件在 `1.1.0+80` 真机上均已导入，但只有 voice_design 接通合成；
切到另两种必须把 `speaker` / `ref_audio` 按上表语义传，不能沿用 voicedesign 的恒 `null` / 必填 `instruct`。

## 3 · 代码里现在真实怎么拼的

```
Mixer.kt VoicePreset.render()          12 维词条 → 身份描述              ← 身份层
ProduceConfig.styleInstruct()         朗读档位/语速/情绪/附加语气         ← 风格层
NonVerbal.apply()                     扫原文拟声描写 → 追加导演指令        ← 只改 instruct
VoiceProfile.buildWithReport(...)     三层合成 → 一条最终 instruct
Pipeline.kt → NativeEngine.ttsSynthesize(text, instruct, speaker=null, lang, knobs)
NativeEngine.kt → JNI → qt_tts_params：instruct 一个字段 + 9 项采样逐字段覆盖
```

三条实锤：

1. **12 维不是官方 API 字段**，是帮用户写 `instruct` 的模板（移植自 ReaderVoice-Mobile，MIT）。
   官方只要一段自然语言属性描述。界面必须标「辅助生成描述」，不能画成 12 个独立旋钮。
2. `Ann.text` 一字不动，所有调教只改 `instruct` —— 正文归 `text`、声线归 `instruct`。
3. **VoiceDesign 每次 synthesize 都按 `instruct` 重新采样音色**；固定 `seed` + 固定身份描述只能**收敛漂移**，
   不保证跨段一致。要彻底锁死得换 CustomVoice 用固定 speaker id。这句必须写进界面，
   不然用户会一直以为是自己没调对。

## 4 · 为什么之前一直做不好

- 层级没分：描述、语气、采样、参考音频摆成一排平级控件，但模型侧是「一条文本指令 / 一组数值 / 另一份权重」三种性质。
- 「固定音色」名不副实（见上条）。
- 照抄别人界面：官方 Playground 的 Speed 是播放层/云端字段，`qt_tts_params` 没有 `speed` / `pitch` 独立字段；
  量化档、GPU 层数也是运行时固定的。**别人有 ≠ 我们这份 GGUF 有。**

## 5 · 分层原则（事实边界，不是画法）

| 层 | voice_design | custom_voice | base |
|---|---|---|---|
| 只读边界 | 当前权重与模式 | 同左 | 同左 |
| 身份 | 自由描述 + 12 维辅助生成 → `instruct` | `speaker` 编号 | `ref_audio` 参考音频 |
| 怎么念 | 朗读档位 / 情绪 / 附加语气 / 拟声 → 拼进同一条 `instruct` | 风格指令 | 拒绝 `instruct` |
| 采样 | 9 项数值，独立字段，与指令同时生效 | 同左 | 同左 |
| 不画 | `speed` / `pitch`、并发、量化档、音色编号 | 参考音频、系统提示词 | 描述、音色编号 |

**能抄的是分层形状，不能抄字段清单**。每轮先查官方文档与随包引擎头，再对比同类优秀软件，最后贴合我们这份权重落地。
官方资料只证明**接口语义**，不证明「这样调就好听」；具体数值要在真实中文小说语料上试听比较。
