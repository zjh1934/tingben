## 重要更正（本轮扒完才发现）

调研报告里写「Android 端 Compose 采样设置页没找到可直接编译的现成 Kotlin 文件」「角色页 UI 只能借鉴字段」——**这两句被本地已有资料推翻了**。
`reference/` 里从立项起就躺着两个完整 Android 工程：

- `reference/OfflineLLM/`：Kotlin + Compose，`SettingsRepository.kt` 把 `temperature / top_p / top_k / repeat_penalty / n_ctx / threads` 全部做成 `KEY_* + DEFAULT_*` 常量 + SharedPreferences；`SettingsScreen.kt` / `SettingsViewModel.kt` 是现成的 Compose 设置页。
- `reference/ReaderVoice-Mobile/`：Kotlin + Compose，`CharacterProfileStore.kt` 是**角色档案的用户修正层**（JSON 原子落盘 + `USER_LOCKED` + 用户值优先合并）；`CosyVoiceVoiceProfile.kt` 有 `schemaVersion / id / profileHash / toJson / fromJson`；`CharacterModel.kt` 有 `canonicalName / entityUid / ALIAS / SAME_PERSON / DIFFERENT_PERSON hardBlock`；`CharacterManagerActivity.kt` 是现成角色管理页；`VoiceDesignEngine.kt` 是 JNI 封装形状。

⇒ **下轮这四块全部有 Kotlin 现成件可抄，不需要自己写组件**。Alexandria 只用来补「别名检测算法」，PocketPal 只用来补「配置版本迁移」。

## 逐块施工图

### ① 角色→音色表：抄 `CharacterProfileStore.kt`，别名算法抄 Alexandria

**照抄对象 A（主体，Kotlin）**：`reference/精选_Kotlin现成件/CharacterProfileStore.kt`
- `character_overrides.json` + `.tmp → renameTo` 原子落盘（跟我们 `AnnCache.write` 同一套）
- `Override(age/gender/role/locked)` + `USER_LOCKED` 语义：**人工改过的字段后续重算不许覆盖**
- `apply(profiles, overrides)`：用户值优先，未修正字段保留抽取结果
- 直接更名成 `core/VoiceCast.kt`，把 `role` 扩成 `voiceDescription` / `voiceProfileId` / `aliases`

**照抄对象 B（字段设计）**：`CharacterModel.kt` 的 `canonicalName / entityUid / entityType(NARRATOR) / ALIAS / SAME_PERSON / DIFFERENT_PERSON hardBlock`；`CosyVoiceVoiceProfile.kt` 的 `schemaVersion / id / displayName / profileHash`。
**照抄对象 C（UI）**：`CharacterManagerActivity.kt` 的角色列表与编辑。

**照抄对象 D（别名算法，唯一需要读算法重写的部分）**：`generate_personas.py`
- `_token_jaccard` (L69) / `_resolve_to_canonical` (L84) / `_resolve_aliases_batch` (L166)
- `alias_of` (L252/L259/L828) / `_NARRATOR_LABELS` (L125，旁白独立)
- `project.py` 的 `_resolve_alias`：渲染前沿链解析到规范角色，共用音色 / 风格 / seed，有链长上限与循环检测

**落到听本**：4B 输出的 `speaker` 只当 `rawSpeaker` 存，**不再当音色键**；合成前 `cast.resolve(rawSpeaker)`；未映射**暂停并提示用户确认**，不静默回落旁白。持久化先单份 `cast.json`（跟 `books.json` / `task_active.json` 同风格），**不引入 Room**。

**不抄**：FastAPI / Pinokio / GPU 热切换 / Python 的 LLM 批量调用（改成「标注后列出待确认角色」的 UI）。

## 联动检查表（下轮提交前逐项跑，用户点名过「改一处联动很多处」）

1. **缓存 key 必须失效**：`AnnCache.bucket` 与合成 WAV 跳过判断，加上
   `voiceProfileId + profileHash（抄 CosyVoiceVoiceProfile）+ samplingHash + instructTemplateVersion`。
   否则改了音色描述，续跑会跳过旧块 → 听起来还是旧声音，界面还假装「续上了」。
2. **断点任务不能动**：`TaskResume.TaskInfo` 的 `think / direct / only` 分桶与 `Producer.start(thinkOverride=...)` 是上轮刚修的，**本轮不许顺手重构**。
3. **模式非法在编译期挡住**：密封类型表达
   `VoiceDesign(instruct必填, speaker禁用) / CustomVoice(speaker必填) / Base(ref必填, instruct禁用)`。
   voice_design 传 `speaker`、Base 传 `instruct` 都会被引擎 `QT_STATUS_MODE_INVALID` 拒。
4. **JNI 签名三处同步**：`NativeEngine.kt` external 声明 ↔ `tingben_native.cpp` 签名 ↔ CI 原生缓存 key（已含 `tingben_native.cpp` 哈希，会自动重编，但要在日志里确认没被跳过）。
5. **逐字 gate 不受影响**：`instruct` 怎么拼都不碰 `Ann.text`，`Annotator.gate()` 的「字符级 == 原文」保持原样。
6. **诊断日志**：加 `VOICE_MODE / PROFILE_ID / PROFILE_HASH / SAMPLING_HASH`，否则真机上分不清「没生效」还是「没保存」。
7. **APK 四项闸门照旧**：无 INTERNET / 无 .gguf / <100MB / 7 个 arm64 .so。
8. **USER_LOCKED 语义**：抄 `CharacterProfileStore.apply()` 时，用户手改过的音色描述不能被后续重算覆盖。
