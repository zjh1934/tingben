# R24 · 拿来主义：三处手搓换成现成项目移植件

**用户指令（原话大意）**：不要什么都手搓，去看别人怎么做的，拿过来改。

这轮不动 native、不动 prompt、不动状态机、不换模型。只把上一轮我自己写的三处核心逻辑，
换成本地 `reference/` 里早就躺着、而且更完整的开源实现，并补上「模型原始产出全文」的自证能力。

## 一、换掉了什么

| 原来手搓 | 换成谁的 | 落在哪个文件 |
|---|---|---|
| `parseWithMeta` 四级 JSON 修复（取最后一个右方括号当闭合） | Alexandria `generate_script.py` 的 `clean_json_string` / `repair_json_array` / `salvage_json_entries` | `core/JsonSalvage.kt` |
| `reconcile` 逐条采纳（只做顺序前缀匹配 + 尾部补齐） | Antioch `script/annotator.rs` 的 `annotate` / `generate_instructs` 采纳管线 | `core/Adoption.kt` |

Python→Kotlin、JSON 库换 Android 自带 `org.json`、字符集扩到中文、
保留听本「原文一字不改」的逐字契约。

### 移植件带回来的能力（上一版一条都没有）

**JsonSalvage**
- 多种 think 标签（`<think>/<thinking>/<reflection>/<reasoning>`）+ 未闭合标签截断
- 括号计数找真闭合，字符串内的方括号不计入层级
- JSON 字符串内裸换行/回车/制表符修复
- 只保留对象条目，过滤 LLM 偶尔吐的裸字符串
- 5 级修复尝试，层级写进日志能看出输出烂到哪一步
- 字段顺序无关（原 Python 正则写死 speaker,text,instruct 顺序）

**Adoption**
- echo 检测：响应复述输入 ≥30 字 → 判为模型在背原文
- 标签前缀剥离：`[角色] ` / `旁白：` / `Pacing:`
- 首句截断、长度 <4 丢弃
- `(speaker,text)` 去重
- 单条 instruct 不合格用 sensible defaults 补齐，**不丢整块**
- 每条丢弃都记原因 → `ANN_ADOPT_DETAIL` 事件

**RawDump**
- 每次 attempt 的模型原始产出**全文**按 run 落盘，带块号/attempt/字数/预算/结束方式
- 只留最近 3 次 run，不长期留存正文
- 诊断页新增「查看 / 复制最近一块模型原始产出（未经清洗）」
- 主事件流 `ANN_RAW_DUMP` 只写路径与计数，不刷屏

### 一处如实订正（不把猜测写成事实）

我原以为「括号计数能在正文含方括号时多救回条目」。本地实测：
- 输出已截断 + 正文含 `]`：旧手搓 0 条、移植件 0 条 —— **没有可观测差异**
- 字符串内裸换行：旧手搓 **0 条**、移植件 **1 条** —— 这才是真实收益

所以括号计数是「结构性正确」，不是「多救回几条」；代码注释已按实测改写，不夸大。

## 四、未采用的现成方案（登记，避免下轮又去搜）

- **llama.cpp GBNF / JSON Schema 约束输出**：官方支持 `llama_sampler_init_grammar`，
  能强制 JSON 语法壳，但不保证逐字回显原文，字符级 gate 仍不可替代；接它要动 native，单独一轮
- **json_repair (Python, mangiucugna)**：与 Alexandria 的 repair 高度重叠，
  Kotlin 端不能引 Python 运行时，不采用
- **Antioch 确定性结构切分** `split_dialogue_paragraph`：会剥离归属语、改写标点，
  与听本「原文一字不改」契约冲突，只采纳其清洗与容错

## 五、如实边界

- 自检全绿 ≠ 真机能用；**R22 的「标注是否真进音频」仍是零证据**
- 这轮解决的是「看不出它标了没」，不是「让它标得更准」
- 真机验法：跑试音短篇 → 设置页「高级」→ 看 `ANN_RAW_DUMP` / `ANN_ADOPT_DETAIL` /
  `ANN_CONTENT`，或复制最近一块模型原始产出全文贴回来
- 前台服务 + PARTIAL_WAKE_LOCK 连续多轮顺延，仍是下一轮第一件
