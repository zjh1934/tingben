## 2. 顺带挖出两个真 bug（都是「一点底都没有」的成因）

**① 看台的段/块索引从来没对齐过。**
`ann_%04d.json` 是**块**索引，`chunk_%04d.wav` 是**段**索引（一块常切成好几段）。
旧 `Workbench` 把两者按同一个 `i` 并排画格 → 第 N 格既不是第 N 块也不是第 N 段，
颜色（来自块）和声音（来自段）永远对不上。R28 起以 `segmap.json` 为唯一真实来源。

**② 续跑后来源全丢。**
R27 只在内存里算 `srcFlags`（哪条是模型标的），进程被杀后从磁盘续上的块不写 `.src` →
看台一片 UNKNOWN 灰格。R28 把逐条 flags 落盘（`flag_%04d.json`），块级 `.src` 只作兜底。

**两个重做动作的产品语义**（都只标脏、禁整章清）：
- **重合成这一段**：只删该段 wav → 合成循环见文件不在就重合成；标注阶段 ann 全在 → **不会重跑 4B**（便宜）
- **重新标注本块**：删该块 ann / flag / src + 该块所有段 wav → 续跑时该块 ann 不在 → **重跑 4B**，对应段重合成（贵，但这是唯一能验证「模型有没有起作用」的干预）

`direct` 档没有 segmap，判定条单独说「本次直接朗读，没有使用语言模型」，**不把「没跑模型」冒充成「模型没采纳」**。
