# 02 · 模型文件结构

> 模型页 / 导入 / 模式切换的现行依据。四个文件名都在上游仓库实际清单里，不是推定。

## 1 · 一个底座，三份模式主文件

| 叫法 | 文件 | 大小 | 规则 |
|---|---|---|---|
| 共用底座 | `qwen-tokenizer-12hz-Q8_0.gguf` | 291 MB | 12Hz 码 ↔ 24kHz 波形，**三模式共用一份，导入一次就够** |
| 描述造音色 | `qwen-talker-1.7b-voicedesign-Q8_0.gguf` | 约 2.1 GB | 一段文字描述造音色，`instruct` 必填 |
| 预设音色 | `qwen-talker-1.7b-customvoice-Q8_0.gguf` | 约 2.04 GB | `speaker` 预设编号 + 风格指令；GGUF 元数据带 `speaker_names` / `speaker_ids` |
| 参考音频 | `qwen-talker-1.7b-base-Q8_0.gguf` | 约 2.1 GB | 一小段参考音频克隆，**拒绝 `instruct`** |

**切模式换 1 个文件，不是 2 个**：换的是 talker 主文件，tokenizer 原封不动。
三份都装进手机约占 6.5 GB；运行时只载一份 talker，`ttsLoad` 每次合成重新加载，切模式自然生效。
模式能力边界以随包 `qwen.h` 为准（见 `01_音频模型调教逻辑.md`）；第三方 GGUF 仓库 README 把
base / customvoice 用途写反了，**没照抄**。

## 2 · 下载地址

上游 `Serveurperso/Qwen3-TTS-GGUF`，国内把域名换成 `hf-mirror.com`：

```
https://hf-mirror.com/Serveurperso/Qwen3-TTS-GGUF/resolve/main/<文件名>
```
备用（原仓完整转载）：魔搭 `leletxh/Qwen3-TTS-GGUF`，
命令行 `modelscope download --model leletxh/Qwen3-TTS-GGUF <文件名>`。

**App 没有 INTERNET 权限**，界面只能「复制地址 → 浏览器下载 → 回来点导入」，不能一键下载。
`1.1.0+80` 真机上四份均已导入。

## 3 · 现行识别与选择规则（`ModelStore` / `Prefs`）

- `Mode` 三值 + 共用底座；`pickFor()` 按 `-voicedesign-` / `-customvoice-` / `-base-` **独有关键词精确识别**，
  不再用泛化 `"talker"` 匹配（那个会把 customvoice / base 误当 voicedesign 加载）。
- `missing()` / `ready()` 口径是「底座 + 至少 1 份模式都在」；顶部缺件提示（书架 / 设置 / 我的音频）读同一处。
- 当前模式存 `Prefs.modelMode`，默认 voicedesign，**不进声音指纹** —— 切模式不误删已合成的 WAV。
- 制作运行期间禁切；`synthesisBlockReason()` 在 `Producer.run` 与两处试音拦住非接通模式，
  给一键切回并真的写回 Prefs，不画假开关、不静默产出坏音频。

## 4 · 模型页现状

一张共用底座卡 + 三张模式卡：文件名等宽完整换行（单行截断会让「需要：」后面一片空白）、
每份配国内镜像与 HF 备用两条地址、单选「启用这个模式」、制作中禁切；
导入中 / 失败 / 重新导入 / 删除重试四态保留。底部在「底座 + 至少 1 个模式都在」时给「回书架，导入一本书」。

## 5 · 还没接通的边界

**只有 voice_design 接通合成**。customvoice 的 `speaker`、base 的 `ref_audio` 在 `Pipeline` 里仍沿用
voicedesign 的恒 `null` / 必填 `instruct`，所以另两种模式只能导入与选中，选中即被拦住。
把它们的输入界面与引擎传参接通，是 `ROADMAP.md` P0 / P1 的事，不在模型页这一层解决。
