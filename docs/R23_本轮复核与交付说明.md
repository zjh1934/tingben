## 零、研究回来后的想法（先给结论）

1. **两个模型的接缝只有「一条 instruct 字符串」。** 官方 VoiceDesign 示例是
   `generate_voice_design(text, language, instruct)`，`qwen.h:285-288` 明写 `instruct required for voice_design`、
   `speaker ... rejected for the other two modes`。所以 4B 的唯一价值是产出「谁说的 + 此刻怎么说」，
   音色身份由固定层拼进 instruct；`speaker=null`、音色表 0 个都不是 bug。协作形状应是
   **4B 语义标注 → 程序逐条校验/补齐 → 拼最终 instruct → TTS 执行**，R22 已按这个形状落地。
2. **「跑半天没结果」的锅在等模型自己停，不在模型笨。** 旧 native 只认 EOG/limit，吐完 `]` 还继续写废话，
   真机 1676 字被 1274 预算腰斩 → 尾部条丢 → gate 全等失败 → 整块换成全旁白直读。加 JSON 闭合早停
   比换模型便宜得多，这是本版最直接的收益。
3. **「全有或全无」是最贵的设计。** Antioch `annotator.rs:24-29,83-94` 的
   *「no LLM needed for structure」「Falls back to sensible defaults if the LLM call fails」* 抄过来做成
   `reconcile()`：前面标对的条目全留，没标完的尾部由程序补成旁白；`result` 拼起来仍严格 == 原文，
   逐字契约一个字没放宽。这一步把「白费力气」变成「至少前半段有戏」。
4. **跨段音色会飘是模式属性，不是代码 bug。** VoiceDesign 每次 synthesize 按 instruct 重新采样；
   官方 README 288-290 给的正路是「VoiceDesign 先合成短参考 → `create_voice_clone_prompt` → Base 复用」，
   原文理由就是 *consistent character voice across many lines*。我们没换权重，只做「固定身份描述 +
   程序剥离身份词」收敛漂移，**不宣称根治**。
5. **语言侧下一步该做「骨架化标注」。** 让 4B 只输出原文区间骨架、由程序重建 `text`，省掉回显 500 字
   这一大段 decode —— 对 9 秒/token 的手机最实在。GBNF 只守 JSON 语法壳，不保证逐字，gate 仍是最终裁判。
   这条要动切分/缓存/评测集，单独一轮，不塞进本版。
6. **订正我以前说错的两条**：`qwen.h:142` 明写 `qt_synthesize ... thread safe` 且 `max_batch>1` 支持批处理，
   「端侧不能并行」不成立，应改成「引擎支持、CPU 收益待真机量」；「小模型回显平行 JSON 会循环」
   只是 Antioch 的工程注释，不是第三方实测，只当风险假设。
7. **物理限制写进产品前提**：两模型不能同时驻留（2.5GB+2GB 必 OOM）、nCtx 4096、CPU 约 9 秒/token、
   TTS RTF≈17。日志和提示词都改不动这些；设计目标始终是「到点停 + 回来点继续」。

## 三、本轮发现并修掉的一处真缺口

用户原话：**「我希望从日志里面能有它标注过后的内容……你没理解我的意思」**。

R22 把全文放进了 `audit/*.jsonl` 和诊断页，但**主事件流 `events.log` 里的 `ANN_CONTENT` 仍是
「前 8 条、每条正文截 70 字、整块 3KB」**。用户历轮贴给我的都是「最近事件（不含正文）」，
那一屏里依旧看不出标了什么 —— 这正是「还是像没标」的最后一环。

**R23 改动**：`Annotator.contentLines()` 改为逐条给 `text` 全文 + `instruct` 全文 + 来源标记，
单块 16KB 才截断；`scripts/check_structure.py` 加 3 个 R23 符号与「不许退回 take(70)」的断言。
主日志轮转 768KB / 800 行仍够（每块约 1~3KB，15 块约 30KB）。
其余一律不动：gate、prompt v2、`Producer.start`、`bucket()`、状态机、native。
