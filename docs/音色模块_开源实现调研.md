# 听本音色模块开源实现调研

## 摘要

可以直接抄的是三层结构：Alexandria 的「规范化角色名 + `alias_of` 别名链 + `voice_config.json`」、Qwen3-TTS 官方的「固定音色描述 / 角色风格 + 逐句情绪指令」分层模板、以及 iris_android 的「DataStore 默认值 → ViewModel 状态 → 保存 → JNI」链路[1][2][5]。不能整段抄的是 `qt_tts_params` 填充：官方头文件没有找到完全同字段的公开脚本，应以本仓库本地 `qwen.h` 的字段顺序、类型、填充宏和 `QT_ABI_VERSION` 为准；公开资料只能确认 Python 默认与官方建议值，不能证明当前头文件字段名和 ABI 版本[4][7]。当前最值得先做的是：①把 `speaker` 彻底改成 voice_design 的 `instruct` 字段，不是传 `null`；②给每个角色保存稳定的 `voice_profile_id`，而不是复用 4B 的临时标签；③把 4B 的块级情绪只写进角色描述之后的局部层；④把采样参数做成版本化 DataStore，旧缓存 key 必须失效。Base 模式的 `instruct` 被明确拒绝，CustomVoice 才有 9 个预置音色；因此本阶段先固定 voice_design，后续切换必须重建 Pipeline 和缓存[4][5]。

## 一、结论与迁移边界

**本模块真正需要复制的是「数据关系与代码分层」，不是某套语言模型接口。** Alexandria 提供的是 audiobook 场景下最接近需求的角色卡：自动提取角色、人工修正、别名指向规范角色、四类声音配置、按角色保存和复用。它已经把跨块一致性问题转化为“同一 canonical name 读取同一 profile”，而不是让上游 4B 每次重新生成文字标签。这层可以直接照抄为 Kotlin data class + JSON/DataStore；其 Python、FastAPI、Pinokio 环境、GPU 模型热切换和克隆/设计后台均不适合搬进 Android[1]。

**instruct 必须拆成“身份固定层”和“表演逐块层”。** Qwen3-TTS 官方的 voice_design 示例把音色身份写成稳定的英文属性串，如性别、年龄、音高、音色、节奏；逐句情绪则由另一条角色风格或调用参数控制。对本项目而言，4B 的 `instruct` 只能描述“此刻怎么说”，不应再发明音色。固定层由 `voice_profile_id` 决定，逐块层由 Qwen3-4B 生成；两者用换行或句号分隔后写入 `qt_tts_params.instruct`[4]。

**采样参数暴露不是新增业务复杂度，而是把已有默认值变成可审计配置。** qwentts.cpp 的默认采样链是 repetition_penalty → temperature → top_k → top_p → softmax → multinomial；官方 Python 建议值为 temperature 0.9、top_k 50、top_p 1.0、repetition_penalty 1.05、max_new_tokens 2048，subtalker 默认 temperature 0.9、top_k 50、top_p 1.0。这些应成为客户端默认值，而不是硬编码到 JNI；只要 UI、DataStore、NativeEngine、JNI 使用同一份配置 schema，就能避免“字段顺序漂移”[4][7]。

**不适用项需要写进类型系统，而不是用 `null` 表达。** voice_design 不接受 `--speaker`；Base 不接受 `--instruct`；`--speaker` 与 `--ref-wav` 互斥；CustomVoice 才有 9 个预置音色。Alexandria 把这种差异表现为声音类型，而不是统一参数表。听本应定义 `VoiceMode`/`VoiceProvider` 密封接口，未实现的能力在编译期隐藏 UI[1][4]。

## 二、角色→音色映射：抄 Alexandria 的 canonical + alias，不抄其存储环境

**Alexandria 已经把小说角色表收敛成 canonical name + alias 图。** 其项目结构把 `app/parse_voices.py` 用于角色/声音提取，`app/generate_personas.py` 负责角色人格生成和 VoiceDesign 分配，`app/project.py` 负责分块与渲染，`voice_config.json` 保存角色配置[1]。关键不是文件名叫 JSON，而是“脚本中的原始说话人标签”与“稳定的 canonical 角色”解耦。听本应保存 `canonical_name`、`aliases`、`voice_profile_id`、`manual_locked`、`appearance_order`，不要让 `speaker` 字符串同时承担显示名、稳定 ID 和音色键三个职责。

| 抄自 | 关键文件 / 类 | 关键字段与手法 | 许可证 | 听本落地方式 |
|---|---|---|---|---|
| Alexandria | `app/parse_voices.py`、`app/generate_personas.py`、`app/project.py` | canonical name、别名合并、角色卡、per-character voice config | MIT；Qwen3-TTS/codec 为 Apache-2.0[1] | 建立 `CharacterCast`，每个角色一个不可变 UUID |
| Alexandria | `voice_config.json` | 角色→声音类型→具体参数；自动保存 | MIT[1] | 先 JSON 文件，后续可选 Room |
| ReaderVoice 类思路 | 语音特征 profile 而非模型路径 | 年龄、性别、音高、语速、音色、情感范围 | 未核验，待核 | 仅作字段设计参考，不复制实现 |
| ensemble-reads | Android 多角色朗读状态层 | 自动分配、手动指定、跨块延续、删除级联清理 | 需核其仓库文件 | 抄状态流转；不应复制其联网/Edge TTS 依赖 |

**别名应延迟解析成规范名，不应原地改名。** Alexandria 允许把 “YOUNG ELENA” 标记为 “ELENA” 的别名；系统需要检测循环、控制链长和旁白例外。移植时建议保留原始标签 `raw_speaker`，新增 `canonical_id`；渲染前做 `resolve(canonical_id)`，返回 `resolved_profile`。4B 后续无论输出“李寻欢”“小李探花”还是“李大哥”，只要人工把它们并入同一规范角色，所有分块都会查到同一个 `voice_profile_id`。

```kotlin
data class CharacterCastEntry(
    val id: String,                 // 稳定 UUID，永不改名
    val canonicalName: String,      // 规范显示名
    val aliases: List<String> = emptyList(),
    val voiceProfileId: String? = null,
    val locked: Boolean = false,    // 锁定后不再被 AI 重分配
    val order: Int = 0
)
```

**跨块一致性的保证来自 profile identity，而不是反复让 4B 重写音色。** 听本把 `voiceProfileId` 放进每个已标注块的只读元数据；合成时先 `cast.resolve(rawSpeaker)`，若返回 `unmapped`，暂停生成并提示用户在角色页确认，而不是自动新造一个音色。这里应抄 Alexandria 的“先生成角色、再渲染分块”的顺序，不能一边生成一边动态建角色。

**角色页必须显示 canonical name、原始标签、音色来源、锁定状态、出场次数与预览键。** 现有 `MainActivity.kt` 设置页负责全局参数；新增 `CharacterCastScreen` 采用可编辑 `LazyColumn`，每项展开为音色类型选择器。参考列表项本身没有找到可直接编译的 Kotlin 开源文件，因此 UI 只能借鉴 Alexandria 的字段与 ensemble-reads 的状态目标，具体 Compose 组件仍由我们写。

**持久化先 JSON、后 Room，不能两种格式并存。** JSON 适合当前离线单进程、易导入导出的场景；字段稳定后再把 `CharacterCastEntry`、`VoiceProfile`、角色出场表分别落 Room。迁移时要给 schema 版本和 `fromJson` 宽容策略：未知 `voice_kind` 转 `UNKNOWN` 而非崩溃，缺失 `voiceProfileId` 转待映射，删除旧角色前级联把分块标记回 `unmapped`。

**联动风险：改角色表会连带污染断点缓存和预览数据库。** 一旦 `voiceProfileId`、音色描述、参考音频或采样配置变化，原 `(text, speaker, gen_knobs)` 缓存就不再等价。建议缓存 key 为稳定 hash，包含 `voice_mode + voice_profile_id + voice_description + ref_hash + sampling_hash + normalized_text`；`voice_profile_id` 本身不随改名变化。Narrator 应始终是独立规范角色，不能与某个普通角色互相 alias，否则旁白会偷走或污染角色音色。

## 三、instruct 分层：抄官方模板，把角色身份从 4B 的逐块输出里拆出来

**VoiceDesign 的 `instruct` 就是音色定义字段，不是可选备注。** 官方示例 `test_model_12hz_voice_design.py` 通过 `generate_voice_design(text=..., language=..., instruct=...)` 生成全新音色，其中 `instruct` 是固定属性描述；另一示例明确使用 “A deep, resonant male voice speaking with a calm and authoritative tone.” 作为身份串[4]。官方模型页也明确 voice_design 的 `instruct` 必填。因此听本当前把 `speaker=null` 只是规避报错，没有真正传入音色；正确做法是把角色固定描述写入 `instruct`，或者在未来 CustomVoice 模式写入 `speaker`。

**固定层应覆盖身份，情绪层只覆盖表演。** 可先抄以下模板：

```text
{age}, {gender}, {pitch}, {timbre}, {pace}. {optional_quality}.
[角色风格] {stable_role_style}
[本段情绪] {block_emotion}
```

其中第一组是 voice_design 的“造声”约束；`[角色风格]` 是同一角色全书复用、可由用户微调的中等时长描述；`[本段情绪]` 是 4B 每块的短句。不要每轮让 4B 重写“年轻男声、低沉”之类固定身份。描述应具体、可感知，避免“好听”“像某人”等主观或侵权表述。

| 官方文件 | 可抄内容 | 关键函数/入口 | 许可证 |
|---|---|---|---|
| `examples/test_model_12hz_voice_design.py` | `instruct` 作为音色设计属性；生成固定音色 | `generate_voice_design`[4] | Apache-2.0 |
| `examples/test_model_12hz_custom_voice.py` | 预置 `speaker`、权重混合、角色风格 `instruct` | `generate_custom_voice`、`create_custom_voice_prompt`[4] | Apache-2.0 |
| `examples/test_model_12hz_base.py` | 参考音频 + 参考文本、ICL/x-vector、可复用 clone prompt | `generate_voice_clone`、`create_voice_clone_prompt`[4] | Apache-2.0 |
| Qwen3-TTS 官方 README | VoiceDesign → Base clone 的两步复用法 | `generate_voice_design` → `create_voice_clone_prompt` → `generate_voice_clone`[4] | Apache-2.0 |

**“先设计、后克隆”是官方给出的稳定复用法，但不是当前阶段必做项。** 官方建议先用 VoiceDesign 模型生成一小段符合角色特征的参考音频，再由 Base 模型通过 `create_voice_clone_prompt(ref_audio, ref_text)` 创建可复用 prompt；之后每次生成传入 `voice_clone_prompt`，避免重复提取特征并保证多段一致性[4]。这比每次把长描述喂给 voice_design 更像“可复用角色卡”，代价是同时持有 VoiceDesign 和 Base 权重、管理参考 WAV/prompt、并把两次推理接入离线 Android。

**现阶段最实用的 C++ 形状是 `build_instruct()`，而不是把两段文本交给 4B 拼接。**

```cpp
std::string build_instruct(
    const VoiceProfile& profile,
    const std::string& stable_role_style,
    const std::string& block_emotion) {
    std::string s = profile.voice_description; // 年龄/性别/音高/音色/节奏
    if (!stable_role_style.empty()) {
        s += "\n[角色风格] ";
        s += stable_role_style;
    }
    if (!block_emotion.empty()) {
        s += "\n[本段情绪] ";
        s += block_emotion;
    }
    return s;
}
```

`NonVerbal.kt` 若目前注入的是行内标签，需要明确检查这些标签属于哪套模型；不能把某一模型的特殊标签塞进当前 Qwen3-TTS 输入。

| 文件 | 改动 |
|---|---|
| `NativeEngine.kt` | 新增 `VoiceProfile`、`buildInstruct(profile, roleStyle, blockEmotion)`；先查角色映射，再组合 instruct |
| `Pipeline.kt` | 4B 输出只消费 `{text, speaker, instruct}`；新增 `resolved_voice`；禁止用 LLM 文本重写音色身份 |

**联动风险：instruct 模板变化会让所有历史缓存失效。** 即使 `voice_profile_id` 不变，增加“角色风格/本段情绪”分隔符也会改变输入；模板版本必须进入缓存 hash。4B 的 prompt 还应约束它只输出短情绪句，不能输出“年轻女声”等固定属性，也不能编造 speaker ID。CustomVoice 9 个预置音色名在小写、下划线、语言支持上可能与模型内部表不同，必须从已加载模型/头文件或可信模型文档获取，不应硬编码猜测[4][5]。

## 四、采样参数：抄“配置中心 + UI + 保存”链路，JNI 结构体必须回归本地头文件

**qwentts.cpp 的公开 API 是单一头文件、纯 C99、`qt_*` 前缀。** 官方示例先用 `qt_init_default_params(&iparams)` 填初始化参数，再用 `qt_tts_default_params(&params)` 获得完整默认合成参数，最后逐个字段赋值并调用 `qt_synthesize()`[4][7]。这意味着听本不应自己“发明”一个 JSON 再在 JNI 里重新解释所有含义；正确做法是先默认、再覆盖、再传递同一 ABI 结构体。

**公开资料能确认默认值，不能证明本地 `qwen.h` 字段顺序和 ABI 一致。** 官方 Python/CLI 默认参考值为：

| 参数 | 建议/默认 | 听本 UI 初值 | 备注 |
|---|---:|---:|---|
| `seed` | 随机 | `-1`（跟随实现） | 需以 `qwen.h` 的 `-1`/特殊值语义为准 |
| `temperature` | 0.9 | 0.9 | Talker/主模型 |
| `top_k` | 50 | 50 | 主模型 |
| `top_p` | 1.0 | 1.0 | 主模型 |
| `repetition_penalty` | 1.05 | 1.05 | 主模型 |
| `max_new_tokens` | 2048 | 2048 | 需按最大块长度限制 |
| `subtalker_temperature` | 0.9 | 0.9 | 代码预测器 |
| `subtalker_top_k` | 50 | 50 | 代码预测器 |
| `subtalker_top_p` | 1.0 | 1.0 | 代码预测器 |

官方 Rust `qwen-tts` 的 `GenerateConfig` 给出 `from_json`、`from_file`、`merge` 和 `effective_max_tokens`，这正是听本需要的“文件/默认值 → 用户覆盖 → 最终值”模型；但其结构体名属于 Rust crate，不能直接变成 C 字段名[7]。`qwentts.cpp` 的 ABI 通过 `QT_ABI_VERSION` 防止结构体增长破坏旧绑定，因此 JNI 侧应读取并断言版本，不能仅凭编译通过就假定兼容[7]。

**最稳的 JNI 形状是先收 Kotlin 不可变配置对象，再在 C++ 侧填本地结构体。** 不要用手写 JNI 字符串 `"seed"`/`"temperature"` 和反射式映射；那样看似灵活，实际会把 ABI 字段名、默认值、类型和字节布局三套事实分散到 Kotlin/JSON/JNI。推荐固定一个 `QwenTtsSampling` data class，在 `tingben_native.cpp` 内转为 `qt_tts_params`。

```kotlin
data class QwenTtsSampling(
    val seed: Long = -1L,
    val temperature: Float = 0.9f,
    val topK: Int = 50,
    val topP: Float = 1f,
    val repetitionPenalty: Float = 1.05f,
    val maxNewTokens: Int = 2048,
    val subtalkerTemperature: Float = 0.9f,
    val subtalkerTopK: Int = 50,
    val subtalkerTopP: Float = 1f,
)
```

```cpp
// tingben_native.cpp（字段名待与本地 qwen.h 逐项核对）
qt_tts_params p;
qt_tts_default_params(&p);
p.text      = text.c_str();
p.lang      = lang.c_str();
p.instruct  = resolved_instruct.c_str();
p.seed      = static_cast<uint32_t>(sampling.seed); // 仅当本地类型匹配
p.temperature          = sampling.temperature;
p.top_k                = sampling.topK;
p.top_p                = sampling.topP;
p.repetition_penalty   = sampling.repetitionPenalty;
p.max_new_tokens       = sampling.maxNewTokens;
p.subtalker_temperature = sampling.subtalkerTemperature;
p.subtalker_top_k      = sampling.subtalkerTopK;
p.subtalker_top_p      = sampling.subtalkerTopP;
```

**JNI 命名也应照抄官方 `qt_*` 前缀，避免与原项目已有 `llama.cpp` 参数混淆。** 建议 native 方法为 `synthesizeQwen(text, lang, instruct, samplingHandle)`，内部把 `samplingHandle` 对应的只读配置复制到 C++ 栈结构体。不要扩展现有 `NativeEngine.kt` 的 7 参数字符串接口：那会重新回到“字段顺序隐式编码在 JNI 签名”的老问题。

| 抄自 | 文件 / 函数 | 可抄内容 | 许可证 | 听本用法 |
|---|---|---|---|---|
| qwentts.cpp | `src/qwen.h`、`examples/*.sh` | 先 default、再覆盖；voice_design/custom/clone 的 CLI 参数形状[4][7] | MIT；模型/codec Apache-2.0[7] | 抄调用顺序，不抄 shell |
| qwen-tts（Rust） | `GenerateConfig::from_file`、`merge`、`effective_max_tokens`[7] | 三层默认值解析 | 待核具体 crate 许可证 | 抄 schema/合并算法 |
| reachy_conv_app | `qwentts_cpp_backend.py` 的 `__init__` | seed/temperature/top_k/top_p/repetition_penalty/max_new_tokens/do_sample 作为配置字段[6] | 待核 | 仅作默认值交叉验证 |
| iris_android | `ParametersScreen.kt`/`MainViewModel.kt`/`LLamaAndroid.kt` | Slider→ViewModel→保存→JNI；专用采样参数方法[2][3] | 待核 | 抄链路，不抄 llama.cpp 参数名 |

| `Pipeline.kt` | 每次合成取当时采样快照；日志打印实际生效值而非 Kotlin 默认值 |

**联动风险：采样参数变化会制造“相同文本却不同音频”。** 若 `seed`、temperature 等没有进入缓存 key，断点恢复会拼出前后音色/节奏不一致的 WAV。反之，若把所有参数都误当作输入 key，用户调低 temperature 也无法重试同一段。应区分：稳定身份参数进入最终缓存 key；纯预览/测试参数可另设“忽略缓存”开关。采样默认值升级时要保留旧 schema，避免旧配置被错误合并。

## 五、Android 设置页与角色音色 UI：抄 iris_android 的单向数据流，自己实现 domain 模型

**iris_android 最适合照抄的是“默认值—状态—保存—native”而不是它的具体 LLM 字段。** `ParametersScreen.kt` 使用 `Slider`、`SettingSection`、实时数值展示和 Save/Reset；`MainViewModel.kt` 持有 `user_thread`、`topP`、`topK`、`temp`；`LLamaAndroid.kt` 把这些值经 JNI 传入 native，并在加载模型时重建 sampler[2][3]。听本应沿用同一单向数据流：DataStore 默认值 → `ViewModel` 状态 → Compose → 用户保存 → 重新读取 → 每次合成快照。

**采样页需要两类控件：连续值用 Slider，离散值用步进输入。** iris_android 将 `temperature/top_p/top_k/threads` 放在同一参数屏，底部 Reset 与 Save；听本应把全局 TTS 与逐角色参数分开，避免用户误以为 seed 是全局音色 ID。推荐分组如下：

```kotlin
TtsParametersSection(
    seed = state.seed,
    onSeedChange = viewModel::setSeed,
    temperature = state.temperature,
    onTemperatureChange = viewModel::setTemperature,
    topK = state.topK,
    onTopKChange = viewModel::setTopK,
    topP = state.topP,
    onTopPChange = viewModel::setTopP,
    repetitionPenalty = state.repetitionPenalty,
    onRepetitionPenaltyChange = viewModel::setRepetitionPenalty,
    subtalkerTemperature = state.subtalkerTemperature,
    onSubtalkerTemperatureChange = viewModel::setSubtalkerTemperature,
    subtalkerTopK = state.subtalkerTopK,
    subtalkerTopP = state.subtalkerTopP,
    maxNewTokens = state.maxNewTokens,
    onReset = viewModel::resetTtsParameters,
    onSave = viewModel::saveTtsParameters
)
```

**角色页应优先可编辑列表，不是通用设置页。** 每项展示 canonical name、原始标签数、音色模式、锁定状态、出场次数和试听按钮；点开进入编辑页，可改规范名、别名、音色类型、固定描述、角色风格、参考音频、采样覆盖。预览时复用正式 `Pipeline.kt`，但生成临时 WAV 并标记“不进入本书断点缓存”。ensemble-reads 证明 Android 需要自动分配、手动指定、跨块延续和删除级联，但没找到可直接引用的 Kotlin 源文件；因此只能借鉴语义，不能宣称照抄代码[8]。

**参数页和角色页不能共用同一个“save 即立即生效”语义。** 全局采样参数保存后可以立即进入下一次合成；角色修改却可能使旧缓存过期。更稳妥的做法是：保存角色表后返回状态 `dirtyForBooks: Set<BookId>`；用户开始渲染时主动重建受影响分块。切勿静默后台重算整本书——这会消耗大量存储和 CPU，并让断点进度不可预期。

### 移植改动

| 文件 | 改动 |
|---|---|
| `MainActivity.kt` | 设置页新增 TTS 采样、音色分层默认值、角色音色入口 |
| 新增 `TtsParametersViewModel.kt`、`RoleCastViewModel.kt` | 前者保存全局配置；后者保存 canonical/alias/profile 并校验循环引用 |
| 新增 `TtsSamplingScreen.kt`、`RoleCastScreen.kt` | 采样控件；角色列表、别名合并、锁定与删除级联确认 |
| `Prefs.kt` | DataStore schema v1；默认值、迁移、备份导出/导入 |
| `Pipeline.kt` | 在合成前取采样快照；角色 dirty 时让缓存失效 |

**联动风险：Compose 局部 `mutableStateOf` 会让设置看似生效、实际未持久化。** 所有值必须以 DataStore 为唯一真源，屏幕离开/保存时再提交；同时保存采样参数和角色表时必须校验事务边界。若先改角色、再改采样，不能让前者使用旧采样快照。导航返回时丢弃未保存草稿，避免退出设置页误写全局配置。

## 六、下轮最小可交付

**第一步：冻结数据模型与模式类型（无 JNI）。** 抄 Alexandria 的 canonical/alias，定义 `CharacterCastEntry`、`VoiceProfile`、`VoiceProvider`、`ResolvedVoice`，加入别名循环校验和旁白例外。验证：同一 canonical 的两个 raw speaker 在单元测试中解析到同一 profile；循环别名被拒绝。

**第二步：实现 instruct 分层并接入现有 `Pipeline.kt`。** 抄官方 voice_design 的固定属性模板，把 4B 的 `instruct` 限定为逐块情绪，固定描述来自角色 profile。验证：输出 `instruct` 不含音色发明；同一角色跨两个块的身份前缀完全一致，只有情绪层不同。

**第三步：把全局采样参数接进 DataStore 和 `NativeEngine.kt`。** 抄 iris_android 的默认值—ViewModel—保存链路。验证：默认配置与官方参考值一致；保存后重启仍恢复；采样参数进入缓存 hash 后旧段被重算。

**第四步：先在 `tingben_native.cpp` 填本地 `qt_tts_params`。** 对照本地 `qwen.h` 逐项填 default、seed、主模型与 subtalker 参数，断言 `QT_ABI_VERSION`。验证：用同一 text/seed 重复生成字节级一致；非法 voice_design/instruct 模式返回明确错误，不崩溃。

**第五步：角色页与缓存失效联调。** 抄 Alexandria 的角色卡字段和 ensemble-reads 的跨块目标，实现可编辑列表、锁定、别名和预览。验证：修改 profile 后，受影响的书进入 dirty；未改角色复用缓存；删除角色产生 `unmapped` 而非静默旁白。

这五步完成后才适合评估 CustomVoice 9 预置音色或 Base 两步克隆：前两步解决身份稳定，中间两步解决参数正确性，最后一步才解决音色来源扩展。

## 七、明确不抄/不做

**不抄 Alexandria 的 Python、FastAPI、GPU/LLM 基础设施。** 它是桌面/服务器工作流，含模型下载、Pinokio、显存和并发批量；听本是 Android arm64-v8a、无网络、单设备、长任务，不能照搬进程模型、参考音频路径解析和 TTS 后端切换[1]。

**不把 voice_design 误当作音色表模式。** voice_design 通过自然语言描述即时造声，没有 Qwen3-TTS 官方 9 预置音色的固定注册表；9 个音色属于 CustomVoice。VoiceDesign 传 `--speaker`、CustomVoice 不传 `--speaker`、Base 传 `--instruct` 都会触发模式校验[4][5]。

**不做 Base 克隆后再写 instruct 的当前期需求。** 官方明确说明 Base 的克隆音色不接受 `instruct` 方向；Alexandria 也对克隆音色忽略 character style。即使未来接入 Base，角色风格只能走固定音色特征/clone prompt，不能沿用 voice_design 的两层 instruct 模板[1][4]。

**不把 Qwen-Audio-3.0-TTS 或 Qwen3-TTS 以外的行内标签搬进来。** “`[laughs]`、`[sigh]`”等标签属于其他模型/标记约定，不是当前 `Qwen3-TTS-12Hz-1.7B-VoiceDesign + qwen-tokenizer-12hz-Q8_0` 已验证输入。应让 `NonVerbal.kt` 在不知道标签语义时保留原文或显式拒绝，而不是静默映射。

**不手搓 JSON-to-C struct 的通用反射映射。** 公开 Rust 有 `from_json`、Python 有参数合并，但没有找到与本地 `qwen.h` 字段、ABI 版本和 C 类型完全对应的脚本。可以抄算法思想，JNI 绑定必须手写并以本地头文件为准[7]。

**不把 Alexandria 的 LoRA、VoiceDesign 保存设计、克隆参考库等全部列入 MVP。** 当前权重是 VoiceDesign；CustomVoice、Base、LoRA 涉及模型热切换、额外权重、参考音频管理和许可证边界。它们适合放在后续模式扩展，不应阻塞角色映射和采样参数下轮交付。
