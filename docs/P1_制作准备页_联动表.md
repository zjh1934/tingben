## 4. 不进指纹 / 不进分桶的理由（写清免得以后又有人加）

- `gapMs` **不进 `produce_stamp`**：静音只在合并阶段插入，分段 `chunk_*.wav` 内容完全不变。成品每次是新的 UUID，天然重新合并。
- `gateRetries` **不进指纹**：只影响标注阶段重试次数，不影响已产出的 WAV。
- 整个 config **不进 `bucket()`**：分桶只管「哪套标注缓存」（direct / think / only）。风格是合成期的事，换风格应该「复用标注、重合成」，不是「重跑 4B」。

### 一次失败记录（run 27）

`ProduceConfig.kt` 的 KDoc 里写了 `KEY_*/DEFAULT_*`，**`*/` 提前闭合块注释**，后面十几行变成顶层声明 → 上百条 `Expecting a top level declaration`。已改成「KEY 常量与 DEFAULT 常量」，并全仓扫描其它 `.kt` 无第二处。

教训补进 R19 纪律：**本地静态检查要加一条「块注释内不得出现 `*/` 字面量」**，括号计数抓不到这类错误，只有编译器能抓 —— 所以「改完先验证再打包」不能省掉 CI，但也不该把这种低级错留到 CI 才发现。
