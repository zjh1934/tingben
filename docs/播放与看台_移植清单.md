# R18 · 音频页 / 工作看台 / 书架边界 —— 移植清单

## 0. 用户提的三件事，先给结论

1. **音频页太简陋** → 重写为完整播放器：播放/暂停、上一条/下一条、±15s、进度条拖动、时长、状态、关闭。
2. **工作看台要能按段预览** → 进度页加「分段看台」折叠卡：一行 8 个小胶囊 `1 2 3 4…`，绿=已有声音 / 蓝=已标注 / 空=还没轮到；点一格展开该段原文预览 + 试听。
3. **书架一直膨胀** → 不是错觉，有两个真因，见 §2。**书架只放原书，成品不进书架。**

另外用户明确要求：**不要手搓，找现成代码改写**。本轮所有 UI 结构都有出处，见 §1。

## 2. 书架为什么会「一直膨胀」（两个真因，都已修）

### 真因 A：导入无去重（书架真的会多条目）
`BookStore.add` 每次都无脑 `UUID.randomUUID()` 新建一本。反复用「打开方式 / 分享 / 粘贴」打开同一份 txt，书架就多一本。
**修**：`Book` 增 `sha`（SHA-256 正文指纹），`add()` 先按「同名 + 同指纹」查旧书，命中直接返回、不写新文件，事件记 `BOOK_IMPORT_DUP`；旧数据（`sha` 为空）用「同名 + 同字数」兜底。导入 Toast 区分「已加入」/「已经在书架上了」。

### 真因 B：成品冒充整本（体感上「一章杠到书架上」）
旧版把每次产出写死 `audio/<bookId>.wav`：
- 做第 1 章和做第 3 章**互相覆盖同一个文件**；
- 音频页把文件名当 `bookId` 查书名 → 一章的成品显示成整本书名。

所以看起来像是「做了一章，书架上又多了一本整书」。**实际它没进书架，是音频页把它显示成了整本。**
**修**：新增 `AudioLibrary`——成品用独立 UUID 命名 + `audio/index.json` 记录「书名 / 范围 / 制作方式 / 时间 / 字节」；范围显示「第 3 章」「第 1–3 章」「整本」；旧成品兼容为「整本（旧版）」，不会丢。

### 信息架构（三层，互不增长）

| 区域 | 放什么 | 什么时候增长 |
|---|---|---|
| **书架** | 你导入的源文本（txt / epub / 粘贴） | 只在导入**新内容**时 |
| **任务** | 制作记录（选章、模式、断点、状态） | 每次起一个任务 |
| **我的音频** | 做好的音频成品 | 每次成功产出一条 |

做一章 → 书架不变、任务多一条、音频多一条「书名 · 第 3 章」。

## 3. 联动检查（改一处会带到的地方，逐个过）

| 点 | 风险 | 处理 |
|---|---|---|
| 成品路径 | 从 `audio/<bookId>.wav` 改成 UUID | `AUDIO_REGISTER` 事件、`TaskResume.output` 绝对路径照常可用 |
| 章节 sidecar | 原来 `${bookId}.chapters.json` 会被覆盖 | 改成 `${成品id}.chapters.json` |
| 「去听」按钮 | `screen = AUDIO` 但不 `refresh++`，新成品列表读不到 | 补 `refresh++` |
| 音频页列表 | 原来只认 `<bookId>.wav` | 改读 `AudioLibrary.list()`，兼容旧文件 |
| 音频页删除 | 原来没有 | `AudioLibrary.remove()` + 本地 `localTick` 触发重读 |
| 播放器释放 | 切页 / 收起看台时 MediaPlayer 泄漏 | 两处 `DisposableEffect(Unit) { onDispose { release() } }` |
| 分段数据 | 标注块 `ann_%04d.json` 与音频段 `chunk/direct_%04d.wav` **索引不一一对应**（一块可能切成多段） | `Workbench` 分开如实列，不假装对齐 |
| 分段数量 | 长书几百段会刷屏 | 只列前 60 段 + 「后面还有约 N 段」 |
| 看台刷新 | 不刷新就看不到新段 | 复用进度页每秒 `tick`，重读 `TaskResume.load()` + 扫目录 |
| 逐字 gate / prompt v2 / native / 状态机 | 本轮范围外 | 一行未动，静态检查确认 |

## 4. 验证口径

- 本地：14 个 Kotlin 文件括号平衡、关键符号齐、旧逻辑零残留、`check_structure.py` 通过。
- CI：编译 + APK 闸门 + 拆包核对（结果见 `STATUS.md` R18 追加）。
- **真机仍是零证据**。要验三件：
  1. 对同一 txt 连续用「打开方式」两次 → 书架条目数不变；
  2. 做「第 3 章」→ 「我的音频」显示「书名 · 第 3 章」，不是整本；再做第 5 章 → **两条成品都在**，不互相覆盖；
  3. 进度页展开「分段看台」→ 小格随合成逐个变绿，点绿格能试听那一段。

## 5. 明确没做的（别假装做了）

- Media3 / MediaSession / 锁屏通知 / 后台播放：会动 Gradle、权限、前台服务，单独一轮。
- 睡眠定时、书签：PaperBack 有，本轮没做。**倍速已做**（1 / 1.25 / 1.5 / 2x 循环，`PlayQueue.setSpeed`）。
- 段级「重做这一段」：需要把 `Workbench` 的只读扫描升级成可写，牵动 `AnnCache` 与 `Producer`，下一轮。
- 分段看台的展开动画：SSCompose 有 `AnimatedVisibility`，本轮用原生 `if`，视觉上一样能折叠。
