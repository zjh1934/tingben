## 一、先把「空间分配」量化（这是这轮唯一的主问题）

同一屏 768dp 内容区，按 `MainActivity.kt:893–1163 / 473–541` 逐块量：

| 现状 `+68` | dp | v11 | dp |
|---|---|---|---|
| 导航/折叠控制（←书架 + 收起↑ + 22dp 手势条） | 90 | 顶部细状态条（小按钮 + 进度条 + 百分比 + 一行状态） | 56 |
| 34sp 紫色大字百分比 | 40 | 五步横排（下方 3dp 色条） | 41 |
| 核心卡其余（stage / 进度条 / 已完成 / message / heartbeat / bar3） | 138 | 语言模型一行（默认折叠） | 36 |
| 五步**竖排**（5 步 20 个字占 130dp） | 130 | **分段看台：铺 `s.text` 正文** | **491** |
| 语言模型卡（独立整卡） | 66 | 其余留白 / 滚动 | 144 |
| 分段看台（**默认折叠，正文 0dp**） | 58 | | |
| 整宽大按钮（46/48dp + 空 TextButton 占位） | 64 | | |
| 贴底常驻任务条 | 40 | | |

**结论**：现状里真正该看的「文本模型处理完、送进声音模型的正文」占 **0dp**；而大字、竖排五步、整宽按钮、返回/收起/手势条、任务条加起来 **324dp ≈ 42% 可视区**。v11 把正文给到 **491dp ≈ 64%**，控制/装饰类压到 **133dp ≈ 17%**。

这就是「该大的不大、该小的不小」的具体答案，不是换配色或圆角。

## 三、8 处我自己拍板（每条一句话可推翻）

1. **抽屉怎么给进度一个位置**：不新增第 9 项、不把「任务」改名；任务中心页原样保留，从「任务 → 查看实时进度」进本页。进度信息就这样收进左侧那一列，四项操作一个不丢。
2. **删任务条后留哪些入口**：留目录页「进度页 ›」、制作页「查看进度」、任务中心「查看实时进度」三个；「去任务页 / 去试听」由抽屉已有的「任务 / 我的音频」承接，不新建页面。
3. **第 5 步与四步文案**：「完成」保留；五步照源码「拆章 / 理解文字 / **生成声音** / **整理音频** / 完成」，不按口语改成「合成音频 / 音频整理」。
4. **色块长什么样**：每格**下方 3dp 小色条**，不是整条色带；**不做「正在做」半透明中间态**，正在的那一步只把文字加粗、下面无色块。
5. **数字格子与详情**：主视觉换成正文；格子降为右侧细索引条，点段才出 `speaker｜instruct` / 试听 / 重合成 / 重新标注。
6. **「不是看他处理的哪些文字」指什么**：按「图例 + 溯源元信息不做主视觉」处理，收进点段详情；**数据一条不删**（v10 差点按删除处理）。
7. **按钮几态**：只有「停止 / 继续制作」两态，**没有「开始」**（开始制作在 `ProduceScreen:854–870`）；v10 凭空造的第三态撤回。
8. **任务条展开分支**：整条删，「去任务页 / 去试听」由抽屉承接，确认。
