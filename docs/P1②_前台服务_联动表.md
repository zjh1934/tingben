# P1② 前台服务 · 联动表（R26 开工前先列）

> 用户纪律：改一处联动很多处、改完要验证、别手搓、各自独立一轮不合并发版。
> 本轮只做 **前台服务 + PARTIAL_WAKE_LOCK + 通知**，P1③ 段级重做 / P2 一律不夹带。
> 依据：`docs/后台保活与浮窗_调研.md`（官方前台服务、Doze、dataSync 约 6h 超时、无障碍/浮窗不成立）。

## 1. 不手搓：抄谁、改什么

| 现成件 | 抄的形状 | 改成听本的 |
|---|---|---|
| `reference/ReaderVoice-Mobile/app-android/.../ChapterDirectorService.kt`（MIT） | `ACTION_START/ACTION_CANCEL`、`createChannel()`、`startForegroundCompat(..., FOREGROUND_SERVICE_TYPE_DATA_SYNC)`、`buildNotification()` 打开 + 取消两个 PendingIntent、`stopForegroundCompat()`、`START_NOT_STICKY` | 不搬它的 runner；宿主只负责「通知 + 唤醒锁 + 停止入口」，推理仍由 `Producer` 协程跑 |
| `reference/ReaderVoice-Mobile/app-android/.../VoiceDesignService.kt`（MIT） | `onStartCommand` 立刻 `startForeground`、finally `stopForeground(STOP_FOREGROUND_DETACH)` | 结束通知保留「已完成 X/Y」，点开回书架 |
| 同仓 `app-android/src/main/AndroidManifest.xml` | 4 个权限 + `<service android:foregroundServiceType="dataSync" android:exported="false">` | 原样照搬声明形态 |
| 官方文档（调研报告 [1][5][8]） | FGS 必须可见通知；dataSync 语义=本地数据处理；PARTIAL_WAKE_LOCK 不防 Doze/LMK | 通知如实写「本地制作」，不伪装 mediaPlayback；唤醒锁**按块**持有、带 30 分钟硬超时 |

**明确不做**：无障碍服务、模拟点击、SYSTEM_ALERT_WINDOW 浮窗、为保活而亮屏、`START_STICKY` 自动重启、后台偷偷 startForegroundService、自动续跑伪装。

## 2. 联动点（12 处，逐个过）

| # | 文件 | 改动 | 为什么要一起改 |
|---|---|---|---|
| 1 | `AndroidManifest.xml` | +4 权限（FGS / FGS_DATA_SYNC / POST_NOTIFICATIONS / WAKE_LOCK）+ service dataSync 声明 | 缺任一权限在 targetSdk 35 会抛 SecurityException，FGS 起不来 |
| 2 | `ProduceService.kt`（新） | FGS 宿主 + 通知渠道 + 打开/停止 PendingIntent + 按块唤醒锁 | 新能力，形状照抄现成件 |
| 3 | `Pipeline.kt / Producer.start` | `begin()` 在 `scope.launch` **之前**；`finally` 里 `finish()` | startForegroundService 要求 5 秒内 startForeground；早退（缺模型）也必须收掉服务 |
| 4 | 同上 | 用 Activity cast 申请 POST_NOTIFICATIONS（4 个入口全汇到 start，只改一处） | Android 13+ 不授权时通知不进抽屉，FGS 仍在但用户看不见 |
| 5 | `Producer.stop` | 通知切「正在停止…」；服务 `ACTION_CANCEL` 直接复用 `Producer.stop()` | 停止逻辑只能有一份，避免通知里点停止和 UI 点停止行为分叉 |
| 6 | `Producer.emit` | 每块/每段更新通知进度（setProgress） | 通知是后台唯一可见界面，不能一直写「准备中」 |
| 7 | `Producer.run` 两个循环 | 标注块 / 合成段开头 `touch()`：release + `acquire(30min)`；`finish()` 释放 | 按块持有，不整轮数小时常驻；Doze 忽略唤醒锁也要如实写 |
| 8 | `TaskResume` / `bucket()` / `Producer.start` 签名 / 状态机字段 | **一行不动** | 上一轮被「改一处联动很多处」点名；书签格式不变，旧任务仍能续 |
| 9 | `TingbenApp.onCreate → Producer.restore` | 不自动起 FGS、不自动续跑 | 被杀后用户点「继续制作」才从可见界面重新启动 |
| 10 | `MainActivity.kt` | ① 把「推理参数」卡真正挪回 ① 语言模型组（R25 文档写了但代码没挪）；② 任务页「关于后台运行」文案改；③ 高级区加「后台运行设置」跳系统电池优化页；④ 诊断摘要加 FGS 状态行 | 文档与代码对齐；用户能自己设白名单；日志更详细 |

## 3. 状态机边界（不新增状态）

- `busy` 仍是唯一真源；服务只读 `Producer.isBusy()`，不自己存任务状态。
- 服务被杀 / 进程被杀 → `TaskResume` 里 phase=running 被 `restore()` 如实改 interrupted，磁盘块文件全留。
- FGS 结束通知保留（DETACH），不算「任务完成」；完成与否看 `TaskResume.phase` 与 `PRODUCE_DONE`。
- Android 15 dataSync 约 6h 超时 → 到点服务被系统停；不自动续跑，回来点继续。
- 屏幕常亮 `FLAG_KEEP_SCREEN_ON` 保留，但文案明确「只在前台、不等于保活」。
