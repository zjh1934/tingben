# 日志模块重设计 + 标注成品审计（R21）

> 2026-11-04 · 用户插队轮。原计划下一轮做前台服务，这轮按指令改为「日志重设计 + 双模型配合研究」，
> 前台服务顺延到下一轮。

## 1. 要解决的不是「日志太少」，是「看不出模型干没干活」

用户原话三件事：

1. 「一顿跑了一堆，结果它没有打标注」——要能截取模型产出，看**标了几条**；
2. 「标注后的长度合不合适」——要能看到原始产出长度、有效 JSON 长度、拼回原文差几个字；
3. 「我们的规则有没有生效」——v2 提示词里的硬契约要能逐条查 PASS / VIOLATE。

旧日志只有 `ANN_BLOCK_BEGIN / GATE_RETRY / GATE_FALLBACK / ANN_BLOCK_END`，
全是「阶段名」，没有一条回答上面三问。真机 1676 字不收敛、思考档 JSON 被截断，
日志里只留一句「降级直读」，用户只能靠猜。

## 2. 参考了什么、没照抄什么

参考用户历轮贴过来的诊断日志**思路**：静态快照 → 分类事件流（最新在上）→ 一键复制，
人能顺着时间线看出「卡在哪」。这几条全部保留。

**没有照抄**：那是旧「墨听」的调试台形态，事件全是 native 技术词。听本按自己的流水线重排：

- 新增 `AUDIT` 分类，专门放「这一块标了什么」；
- 常态摘要只给结论，模型原始输出与片段进诊断态详情，不刷屏；
- 每块落一条结构化审计到磁盘，不只是往事件流里 append 一行字；
- 复制分两级：摘要（可直接贴给我）与完整日志（含产出片段，仅本机）。

调研里最有用的一条也采纳了：**记流水线事件，不记模型噪声**；摘要与详情分离，
失败用显式码，不静默。

## 3. 两级日志

| 文件 | 内容 | 轮转 |
|---|---|---|
| `events.log` | 用户态：所有事件，行格式保持 `ts \| KIND \| ACTION \| detail` 不变 | 768KB / 800 行 |
| `events_detail.log` | 诊断态：同一条事件额外带 `level` 与 `k=v` 结构化字段，含 `ANN_PREVIEW` 截取片段 | 1.5MB / 2000 行 |
| `audit/run-<id>.jsonl` | 每块一条可查审计；`latest` 记最近 run；只留最近 3 次 run | 按 run 轮转 |
| `crash.log` | 崩溃时写：堆栈 + 200 行环形缓冲 + 最后 10 个块摘要 | 覆盖 |

`EventLog.log` 新增 `level` 与 `fields` 两个默认参数，**所有旧调用点一行没改**，
native 的 `nativeNote(kind, action, detail)` 签名也没动（按 action 前缀自动标 TRACE）。

## 4. 新增 / 增强的事件

| 事件 | 级别 | 记什么 |
|---|---|---|
| `AUDIT_RUN_BEGIN` | INFO | runId、书名、方式、块数、prompt 版本 |
| `ANN_RAW` | INFO | 原始产出字数 / 思考字数 / JSON 候选字数 / 四级修复用到第几级 / 拆出几条 / 失败码 |
| `ANN_PREVIEW` | TRACE | 产出**开头 160 字 + 结尾 80 字**的截取（换行转 ⏎） |
| `ANN_EMPTY` | WARN | 「跑完却没解析出任何标注条目」——用户最担心的那个情况 |
| `ANN_AUDIT` | INFO/WARN | 块级结论：状态、条数、text 字数、长度差、规则通过数、耗时 |
| `AUDIT_SUMMARY` | INFO | 全局：PASS / 缓存续上 / 降级直读 / 零标注、失败码分布、长度合计、废话占比、规则统计 |
| `GATE_RETRY` | 增强 | 带上失败码与该次规则通过数，不再只有「第 N 次」 |
| `ANN_BLOCK_END` | 增强 | 带上通过/降级与耗时 |
| `ANN_WAIT` / `NATIVE_*` | 不变 | 心跳与引擎事件照旧，只额外标了 TRACE 级别 |

## 5. 9 条规则（对着 `prompt_zh.txt` v2 硬契约逐条判）

查的是 **4B 原始产出**，不是 `VoiceProfile.sanitize()` 清理后的结果——
不然「模型到底守没守规矩」就被程序擦掉了。

| 码 | 中文 | 判定 |
|---|---|---|
| `VERBATIM` | 逐字保真 | 所有 text 顺序拼接 == 本块原文 |
| `ORDERED_SUBSTRING` | 有序连续片段 | 每条 text 在原文中按序、无重叠、无遗漏 |
| `JSON_ONLY` | 只输出一个数组 | 去思考/围栏后以 `[` 开头、无代码围栏 |
| `NO_TRAILING_TEXT` | 无解释尾文 | 最后一个 `]` 之后没有非空字符 |
| `NO_INLINE_TAG` | 禁方括号标签 | instruct 里无 `[laugh]` 类标签（本模型会当字念） |
| `NO_IDENTITY` | 不写音色身份 | instruct 里无身份词（复用 `VoiceProfile.hasIdentityTerms`） |
| `COUNT_BOUND` | 条数上界 | 条数 ≤ 句末标点数 + 2 |
| `SPEAKER_OK` | speaker 合法 | 非空、且在活跃角色表或「旁白」 |
| `INSTRUCT_OK` | 指令独立 | 非空、且不写「仍然/依旧/同上/如前/继续」 |

规则中文名集中在 `AnnotatorRules.LABELS`，UI 与校验共用一份，不各写一套。

## 6. 失败码

`EMPTY_ARRAY`（零标注）/ `JSON_SYNTAX_FAIL`（四级修复全失败）/
`CONCAT_LEN_MISMATCH`（能解析但拼不回原文）/ `THINK_TAIL_NOT_CLOSED`（思考被预算截断）/
`PASS` / `CACHED`（从磁盘续上，未重跑 4B）/ `FALLBACK`（降级直读）。
首个差异偏移写进 `BlockAudit.firstDiff`，日志里不贴整段原文。

## 7. 用户在设置页能看到什么

「高级（诊断）」折叠里，每 3 秒跟着任务刷新：

- **静态快照**：版本 / 设备 / 引擎 / 设置 / 模型 / 最近崩溃（原有，保留）
- **标注审计**：一段人话结论（本次几块、零标注几块、长度差多少、废话占比、⚠ 告警）
- 三个小折叠：**逐块明细**（最近 12 块一行一块）、**规则生效**（每条 pass/总）、
  **产出截取**（最近 3 块的开头结尾片段，明确标注「仅本机、有限片段」）
- 两个按钮：**复制诊断信息（摘要）** / **复制完整日志（含产出片段）**

## 8. 边界（刻意不做）

- 不把整本正文写进日志；截取片段按 run 轮转，只留最近 3 次。
- 不因审计改变任何标注结果：审计只读产出，不参与 `gate()` 决策；`gate()` 表达式**一行未动**。
- 不加网络权限、不上传、不新增 Tab、不把审计塞进主界面。
- 不把 `level` 塞进主日志行格式（用户贴过的格式保持兼容）。
