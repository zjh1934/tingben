## 守恒清单（逐字节比对 HEAD）

- `MainActivity.kt` 的 `Screen` 枚举 / `when(screen)` 分发 / `AppChrome` / `chromeOf` / `BackHandler` / 通知回跳 / 外部导入落地
- `Prefs` 除 `setDefaultPerf` 沿用既有入口外不改；`MixerDraft.active()` / `MixerCommit.commit()` 唯一出口不变
- 4B 设置、`prompt_zh.txt` v2、两条制作路径、`bucket()`、`TaskResume`、`ProduceService`、`native/JNI`、`qt_tts_params` 字段、Gradle 依赖
- `ParamSpec.SAMPLING` 9 项 key / 默认值 / 范围一个不动；`TTS_PARAMS_APPLIED` 日志不动
- 唯一生效动词仍是「提交变更」；两态试听仍是独立于提交的两个按钮

## 「自定义输入」必须真生效，不摆假开关

表演层是 ⚠️ 上层项：能改，但模型只看得到拼好的文字或合并参数，徽标不变，不必画成 ✅ 到引擎。

- 朗读档位 / 语速倾向 / 情绪强度：三个小框输入短语 → 按 `朗读:…｜语速:…｜情绪:…` 合并进 `ProduceConfig.extraInstruct` → `styleInstruct()` 末尾拼进 instruct → 提交后新合成生效；读回时按前缀拆回三个框
- 段间静音 / 失败重做：直接写 `gapMs` / `gateRetries`，`fromJson` 由「不在预设列表就回默认」改成范围校验（`0..5000ms`、`0..10`），否则自定义值提交后会被静默重置
- `extraInstruct` 进 `audioStamp()`，改动会按既有机制作废已合成 WAV，不出现「改了没反应」
- `MixerCommit.diff` 补「附加语气」一行，顶部「未提交 N 项」与差异弹层自动带上
- `SCHEMA` 升 2；`fromJson` 宽容迁移：旧书签无该字段一律空串，绝不崩

## 验收（挂 CI 的 r50_verify.py）

1. 源码层：`ParamRow` 无 `label = { Text("精确值"`；数字框 `height(38.dp)` 且 `width(72.dp)`；滑块仍 `weight(1f)`
2. 源码层：表演层 5 个 `ChipRow` 调用全部带 `allowCustom = true` 且各自 `onCustom` 写 `draft`
3. 数据层对拍：默认 `ProduceConfig()` 的 5 个旧字段值不变；`extraInstruct` 默认空；`styleInstruct()` 空串时不改变旧输出；带自定义时含该短语；`toJson→fromJson` 往返保留自定义 gapMs/gateRetries/extra；旧 JSON（无 extra、schema=1）不崩且回空串
4. 源码层：`snapshotFlow` 存在、`jumpLock` 存在与解锁在 `finally`、`AnchorBar` 仍只读传入的 `current`
5. 反向注入 10 例：删任一 `allowCustom` / 去掉 `extraInstruct` 拼接 / 恢复 fromJson 白名单 / 删 `snapshotFlow` / 删 `jumpLock`/`finally` / 恢复带 label 的大框 / 改 9 项任一默认值 / 重新引入 M3 不存在的 `contentPadding` → 断言必须失败
6. 守恒：`ParamSpec.SAMPLING` 9 项 key·def·range 与 HEAD 一致；`commitAll` 唯一；4B/native/prompt 文件未改

## 分轮边界

本轮只做上述三处。**不做**：滑块双模改 BasicTextField、锚点吸顶（现在锚点本来就在滚动区外）、V2 目录页、迷你播放条、固定音色独立 Screen、v4 剩余两处差额。各自单独一轮。
