### 验证脚本自己写错的四处（已修，如实记）

1. `r42_verify.py` 基线把官方字段目录误传成 `Mixer.kt`（实际在 `ParamSpec.kt`），导致基线打印 FAIL 却仍输出 PASS；已改为传 `SPEC` 并把基线结果纳入 `errs`。
2. `ChipRow` 出现次数初版按「每维一次调用」算成 18，实际是 1 定义 + 2 Preview + 1 循环 + 5 表演 = 9；按真实形态订正。
3. `r36_verify.py` 旧断言查 `SettingOption("朗读档位"` 等，R42 改 `ChipRow` 后假红；同步形态 + 补反向用例，不是删断言。
4. `r40_apk_verify.py` 初版把 `096b_personas.py` 列为 dex 零残留，拆包判 FAIL。实查它只躺在 `ParamSpec.UPPER` 的 hint 数据源里，`Mixer.coverage()` 只用 `it.label` 渲染，**任何界面都不显示**；按评审「普通用户视图」口径这是断言误判，已改成检查真正的界面旧文案，并给 `r42_verify.py` 补一条「覆盖表只渲染 label」的可检断言。

> 后两条订正发生在 run 53 之后：验证脚本不进 APK，产物未变；本地 7 套脚本与拆包硬验均重跑全绿，脚本改动以 `[skip ci]` 同步，不另触发构建。
