## 1. 音频模型能调的维度（用户说「我说不上来」的那部分）

分 6 组。**前 3 组是真能调的，后 3 组是只读/结构性的**，界面上明确分开，不混成一张大表单。

### A. 音色身份 · 12 维（instruct ①，全书固定）

来源：官方 VoiceDesign 多属性控制示例（性别·音高·语速·音量·清晰度·流畅度·口音·音色质感·情绪·语调·性格）（Qwen 官方博客 / qwen.ai 模型页），
补齐年龄与「气质」成 12 维；中文词条网格逐字移植 ReaderVoice-Mobile
`training/readerdirector/inference/096b_personas.py`（MIT）的 persona 字段表 （AutoShorts VoiceDesign 12 维预设表）。

| # | 维度 | 例 | 归哪一层 |
|---|---|---|---|
| 1 | 性别 perceived_gender | 男声 / 女声 / 中性 | 身份层（固定） |
| 2 | 年龄 voice_age | 少年 / 青年 / 中年 / 老年 | 身份层 |
| 3 | 音区 pitch_range | 高 / 中高 / 中 / 中低 / 低 | 身份层 |
| 4 | 音色质地 timbre | 清亮 / 温润 / 浑厚 / 沙哑 / 醇厚 | 身份层 |
| 5 | 明暗 brightness | 明亮 / 中等 / 低沉 / 暗 | 身份层 |
| 6 | 颗粒感 roughness | 光滑 / 微粗 / 粗糙 | 身份层 |
| 7 | 气息 breathiness | 低 / 中 / 高（气声） | 身份层 |
| 8 | 分量与音量 weight | 轻 / 中 / 重；音量大小 | 身份层 |
| 9 | 语速 speech_rate | 慢 / 中 / 快（**只写稳定倾向**） | 身份层 |
| 10 | 吐字 clarity | 清晰标准 / 自然 / 略含混 | 身份层 |
| 11 | 口音 accent | 普通话 / 方言 / 无 | 身份层 |
| 12 | 气质 social_style | 儒雅 / 沉稳 / 活泼 / 威严 | 身份层（锚点，不写情绪） |

**纪律（Alexandria `VOICE_REFERENCE.md`，40 组对照实验）**：`description` 管音色物理质感，
`instruct` 管表演；**Anatomy-First 胜出**——模型需要具体声学目标（音区、共鸣、质地）才能
产生稳定声音；纯情绪、人设、场景类描述太抽象，**每一句都会变成不同的声音** （Alexandria VOICE_REFERENCE.md 实验结论）。
这直接解释用户实测的「每一个小段音色都不一样」。

### B. 表演指令 · 4 维（instruct ③，逐段变化）

| 维度 | 例 |
|---|---|
| 意图 / 情绪 + 强度 | 压着怒气、克制 / 标准 / 饱满 |
| 节奏 / 重音 | 语速偏慢、句尾下沉、停半秒 |
| 发声状态 | 气声偏重、声音微颤、尾音下沉 |
| 停顿 | 段间静音 0/300/600ms（制作准备页「仅本次」） |

表演类词**不许混进身份层**（`VoiceProfile.sanitize()` 反向做：把 4B 漏写的身份词剥掉）。

### C. 采样 · 9 项（本轮控制台核心）

本地一手：`qwentts-cpp/src__qwen.h:303-320` + `src__sampling-defaults.h`。

| 项 | 默认 | 作用 |
|---|---|---|
| seed | 42 | 固定可复现；`-1` = 硬件随机 |
| max_new_tokens | 2048 | 12.5Hz → 单次 ≈163.8 秒音频上限 |
| temperature（主 talker） | 0.9 | 抽 c0（语义节奏层）；0 = argmax |
| top_k（主） | 50 | 候选集 |
| top_p（主） | 1.0 | 核采样 |
| repetition_penalty | 1.05 | 采样链第一环 |
| subtalker_temperature | 0.9 | 抽声学码；调低可减少语速抖动与电音感 |
| subtalker_top_k | 50 | 声学层候选 |
| subtalker_top_p | 1.0 | 声学层核采样 |

采样链顺序（README:22）：`repetition_penalty → temperature → top_k → top_p → 多项采样`，
主/副各独立一套 （Qwen3-TTS-X 公开配置 / llama.cpp KV 公式）。Qwen3-TTS-X 公开推荐「稳定高质量」起点：
主/副温度 0.6、seed 42、sub_seed 45，明确标注「调低 sub_temperature 可减少语速抖动和电音感」（Qwen3-TTS-X 公开配置 / llama.cpp KV 公式）。
**注意**：那是另一个项目的配置经验，不是本 GGUF 的实测结论，控制台里只当预设候选。

### D. 合成边界（只读）

`lang=chinese`（显式，不用 auto）、`max_batch=1`（CPU 单 compute worker，`qwen.h:133`）、
`codec_chunk_sec=24.0`（引擎内部分块，`qwen.h:145-159`）、段长 `TARGET_CHARS=110 / SOFT_CAP=260`。
这些属于引擎固定能力或「仅本次任务」，**故意不在调音台重复设一份**，避免出现两份真值源。

### E. 拼接输出（只读）

24 kHz / mono / 16-bit（`qwen.h:102-107`）、段间静音 48 B/ms、WAV 头 44 字节。
响度归一化 / LUFS 对齐 / M4A **都没做**，不画假开关。

### F. 可复现性

`TtsKnobs.hash()`（9 参数）、`Prefs.voiceStamp(c)`（音色 + instruct 模板版本）、
`ProduceConfig.audioStamp()`（本次风格）。改任一项 → 已合成 WAV 自动作废重做（R14 既有机制）。
长语音工程实践建议：为整本书建**不可变 synthesis profile 并 hash 后附到每次请求** （smallest.ai 长语音一致性指南） ——
调音台的「当前生效配置」就是这个 profile 的只读视图。

### 明确不能调（结构层，需换模型/重下）

量化档（Q8_0）、权重模式（voice_design / custom_voice / base）、codec 帧率 12.5Hz、
tokenizer 权重、speaker 表（VoiceDesign 返回 0 个，`qwen.h:384-385`）、
`speed`/`pitch` 独立数值字段（`qt_tts_params` 里物理上没有）、行内 `[gasp]` 标签（另一代模型能力）。

## 2. 控制台怎么设计（本轮落地）

**独立一页「调音台」**：设置页顶部醒目入口卡 → 全屏页。不动底栏 4 Tab（R17 定的信息架构），
只把「设置」Tab 的高亮条件扩到 MIXER。

从上到下 5 块，默认展开前 2 块：

1. **当前生效配置**（只读）：4 组共 18 行，全部生效值一眼看全；「复制进诊断日志」按钮
2. **① 音色身份 · 12 维**：12 维说明 + 10 条现成中文音色网格（点一条直接应用）+ 自由描述框
3. **② 采样参数 · 9 项**：4 组预设 + 9 个细调 + 恢复上游默认值
4. **③ 合成边界 · 只读**：解释为什么这些不在这里设
5. **④ A/B 试听对比**：同句文本、同 instruct，A=当前 / B=选中预设（**不改全局设置**），
   各自试听；每次合成把 9 参数 + instruct 全文 + 指纹写进 `MIXER_AB`

**关键取舍**：之前 9 个参数埋在设置页「声音采样（进阶）」折叠里，只有 3 档固定选项，
改完也看不出现在整体是什么配置 —— 这正是用户说的「控制台上要能显示出来」要解决的。
调音台**不存第二份配置**，全部从 `Prefs` / `ProduceConfig` 读，写也只走既有入口。

**4 组采样预设**（不手搓，来自一手默认值 + 公开推荐配置）：

| 预设 | 值 | 依据 |
|---|---|---|
| 上游默认 | 0.9 / 50 / 1.0 / 1.05 / 0.9 / 50 / 1.0 / 42 | `sampling-defaults.h` 逐字 |
| 稳定朗读 ★ | 主 0.6 / 副 0.6 / rep 1.1 / seed 42 | Qwen3-TTS-X 推荐起点 |
| 戏剧张力 | 主 1.1 / 副 0.8 / seed 42 | 高温度 → 演绎起伏更大 |
| 完全确定 | 主 0 / 副 0 / seed 42 | `qwen.h:308` temperature 0 = argmax |

## 3. 联动表（先列再动，7 处）

| # | 牵动点 | 本轮怎么改 | 没动 |
|---|---|---|---|
| 1 | `Screen` 枚举 + `when(screen)` 分支 | 加 `MIXER` 一项、加一个分支 | `BackHandler` 条件 `screen != LIBRARY` 已覆盖 |
| 2 | `SettingsScreen` 签名 | 加 `onMixer: () -> Unit`，唯一调用点同步传 | 其它 4 个参数不变 |
| 3 | 底栏「设置」Tab 高亮 | 条件扩到 `screen == Screen.MIXER` | Tab 数量、导航结构不变 |
| 4 | 设置页顶部 | 加入口卡（在「作用域」卡之前） | 原有分组、作用域说明不变 |
| 5 | `Prefs.ttsKnobs` 写入 | 只走既有 `setTtsKnobs` / `resetTtsKnobs` | `bucket()`、`TaskResume`、`Producer.start` 签名、`voiceStamp` 机制全不动 |
| 6 | 缓存作废 | 复用 R14 既有 `hash()` → WAV 作废 | 不新增指纹字段、不改分桶 |
| 7 | 日志 | 新增 `MIXER_PROFILE` / `MIXER_AB` 两个事件 | `EventLog` 格式、诊断摘要结构不变 |

**A/B 的隔离**：B 组 knobs 直接构造 `TtsKnobs` 传 `ttsSynthesize`，**不写 Prefs**，
所以试听不会污染长期默认、不会触发全书 WAV 作废。这是能在调音台放心试参数的前提。

**已知边界（如实写）**：`Mixer.snapshot(c)` 的表演层读 `ProduceConfig()` 默认值，
因为「仅本次」预设随任务书签走、不在跨书设置里。控制台里明确标「只读 / 默认」，
不冒充当前正在跑那本书的本次值。要显示实时本次值需把 TaskInfo 传进来，属下一轮。
