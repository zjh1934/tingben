## 一、实查：不是 4 套，是 5 个写入点

评审说「4 种生效时机」。按当前 `+48` 源码逐个核，实际有 **5 个能写「生效态」的入口**：

| # | 写入口 | 时机语义 | 落在哪 |
|---|---|---|---|
| W1 | ① 身份「保存并生效」 | 立即，写长期 | `Prefs.voiceIdentity` + `VoiceProfile` v4 指纹 |
| W2 | ① 九项各自「设定」 | 立即，写长期 | `Prefs` / `TtsKnobs` 9 项 |
| W3 | ② 12 维「写入草稿」 vs「套用」 | 前者不生效 / 后者**直接保存生效** | 草稿内存 / 越过 W1 直写 |
| W4 | ③ 表演层 + ④ 开关「下个任务起」「长期默认」 | 跨任务 / 仅本次 | `TaskBookmark.perRun` vs `Prefs` |
| W5 | ⑥ 预设「应用」「保存」「删除」 | 覆盖？改名？无 diff | `MixerPreset` 库（`.part` 原子落盘） |

再加上 ⑦「当前生效配置」只读快照在页面最底部、⑧ 官方资料索引，形成评审说的「唯一全貌埋底、状态被拆碎」。

**根因一句话**：所有控件都各自持有 `commit` 权，界面没有「待提交」这一层。R38 把身份框改成「按保存才生效」只统一了 W1 与 W3 的一半，W2/W4/W5 仍各自为政。

## 二、统一方案（P0 的目标形态）

**新增唯一编辑态：`MixerDraft`**（`rememberSaveable` + 可落盘，不写 `Prefs`）。
**唯一生效动作：`commit(draft)`**。所有编辑事件只 `update(draft)`，任何控件不得直接写 `Prefs` / `TaskBookmark` / 预设库。

顶部吸顶状态条三段式，读同一份 `active vs draft`：

```
已生效：v4 · 指纹 a8a0…   ｜   未提交变更：3 项   ｜   [查看差异] [提交变更]
```

- 「未提交 N 项」由 `diff(active, draft)` 逐字段算，**不是各控件自己上报**
- 「查看差异」抽屉：`旧值 → 新值` 逐项列表（⑦ 的全貌搬到这里，instruct 给全文不截断）
- 「提交变更」是**全页唯一**动词；删「设定」「套用」「直接保存生效」「应用」「保存并生效」
- `commit` 内统一处理：写 `Prefs` → 重算 `VoiceProfile` v4 指纹 → 判 `voice_stamp.txt` 作废 → 写 `MIXER_PROFILE` / `TTS_PARAMS` 日志
- 「仅本次」项不进 `Prefs`，进 `draft.perRun`，由 `commit` 明确标注「下个新任务起」，**不污染正在跑的续跑书签**

这也是官方 Compose 架构那句「状态只能在一个位置更新、只有一个可信来源，才不会因为状态不一致出 bug」的直接落地 ；「未保存更改 + 离开确认」有现成 `FormViewModel.hasUnsavedChanges` 形状可抄 。

## 三、会牵动的 11 处（改之前先签）

1. `MixerDraft` 新增（状态容器，唯一编辑态）
2. `commit()` 唯一出口（收拢 W1~W5）
3. ① 身份卡：从「保存并生效」→ 上下对照（已生效全文只读灰底 / 草稿可编辑 / diff 高亮），**「清晰自然的中文普通话叙述声…」必须是已生效值，不是静态说明**
4. ① 九项：删 9 个「设定」按钮，行内改值 → 失焦入 draft
5. ② 12 维：只留「生成描述 → 可编辑预览框 → 填入草稿」一条语义；现成网格同样「填入草稿」，**不再直接保存**
6. ② 预览框：从一行标签换成可编辑文本区，随 12 维实时拼串
7. ③/④ 时机文案：抽成统一组件（评审第 17 条，「正在跑的任务不受影响」是写得最清楚的一句）
8. ⑤ 角色行：补音色 chip、未绑定橙色提示 + 全局映射开关给可见提示（**禁静默回落旁白**）、删除二次确认
9. ⑥ 预设：「应用」→「对比并应用」（逐项 diff 弹层再确认）、空名禁存、`untitled` 给重命名/删除
10. ⑦ 降级为「诊断导出」（复制日志 / 指纹 / 并发 / 边界），全貌移交「查看差异」抽屉
11. `MIXER_PROFILE` / `MIXER_AB` / `TTS_PARAMS` / `TTS_PARAMS_APPLIED` 日志：commit 前后各一条，贴诊断摘要能对照「界面填的 vs JNI 实收」

## 五、6 条验收 → 断言映射（每轮发版前跑）

| 验收 | 断言形式 |
|---|---|
| 编辑后顶部计数准确、差异弹层逐项 旧→新 | `diff(active,draft).size == N`，对拍 6 组 |
| 全页只有「提交变更」一个生效动作 | 全量字符串扫描：旧动词 `设定 / 套用 / 直接保存生效 / 应用 / 保存并生效` 零残留（排除预设库内部「保存预设」等非生效语境） |
| 角色未绑定有提示、不静默回落旁白 | 注入「映射开 + 0 绑定」→ 断言出现可见提示且 speaker 不回落 |
| 375px 12 维无溢出 | Compose `@Preview(widthDp=375)` + 禁用 `horizontalScroll` 的源码级断言 |
| 普通视图不出现 `qt_tts_params` / `.py` / § | 可见性断言：仅在「高级」展开态存在 |
| 提交不污染续跑 / 4B | 反向注入：commit 后 `TaskBookmark.perRun` 与 4B Prefs 逐字段零 diff |

外加每轮固定：反向注入全拦下、CI 真 Kotlin 编译、拆包硬验（CRC / 7 个 arm64 .so / 权重 0 / 无 INTERNET / 新符号 / 旧文案零残留）、**直链 blob 与本地 APK 逐字节一致**（R33 翻过车，每轮必核）。

## 六、拿来主义候选（下一轮落地前逐行拉源码，不照抄整页）

按用户纪律「不要什么都手搓」：

- **单一真值源 / 状态提升**：官方 Compose 架构「单向数据流、状态只能在一个位置更新」 [developer.android.google.cn/jetpack/compose/architecture]；官方 *Other considerations*「source of truth 归更靠近根的一方、`SideEffect` 发布给非 Compose 代码」——正好用于 `commit()` 把 draft 发布给 `Prefs`/JNI
- **未保存更改 + 离开确认**：`FormViewModel.hasUnsavedChanges` / `onDataChanged` / `onDataSaved` 形状 [imooc.com/article/370869]
- **折叠分区设置页**：CleverKeys `CollapsibleSection(title, expanded, onExpandedChange)` + `AnimatedVisibility`，以及 `ConfigurationManager` 的 `ConfigChangeListener`（单一 Config 实例、观察者解耦刷新） [Settings System Architecture]
- **分区 + StateFlow 设置页**：ZOOZ `SettingsViewModel` 把每区 Flow 合成 `StateFlow`，`SettingSwitch / SectionTitle` 复用组件 [engineering.zooz.com]
- **锚点滚动**：官方 Compose 示例 `rememberLazyListState` + `firstVisibleItemScrollOffset` + `TopAppBar` 吸顶 [composeexamples.com]
- **应用级状态所有者**：`AppState` 单一 owner 思路（仅取「一个地方理解应用状态」，**不引 God Object、不新增依赖**）

许可证状态如实标：官方文档/示例可直接用形状；CleverKeys、ZOOZ、慕课网为文章片段，**R40 落地前需核仓库 LICENSE 并补 `THIRD_PARTY_NOTICES.md`**，未核实前只抄结构不复制代码。GPL 件一律只看形状。
